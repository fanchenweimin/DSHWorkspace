## 1. 心魔成活率 → ✅ 已裁决：**与心性成正比**

**用户口径（r35）**：「心魔成活率，40（0-39）以下触发心魔，存活率与心性成正比，0 时为 0，39 为 0.1。」

| | 结论 |
| --- | --- |
| 触发区间 | 心性 **0–39** |
| 存活率 | `p(活) = 0.1 × 心性 / 39`（**成正比**） |
| 边界 | **0 → 0**、39 → 0.1 |

- 旧 docs 的 `0.10 × 心性 / 39` 本来就与这条一致 → **保留**。
- `.tmp` r13 主张的"反比（3.9÷心性）"被**否决**。
- 落点：`需求/01` §3.5、`设计/02` §5。

## 2. 心性衰减与地板 → ✅ 已裁决：**定时任务，只到 60 为止**

**用户口径（r35）**：「心性衰减是一个定时任务，在角色没进入修心境界时，心性 > 60 则会按设定递减心性。当心性 <= 60 时，不再由该定时任务扣减。」

- 定时任务只约束"自然衰减"，**≤ 60 就停**。
- **但事件与心关失败照样能扣到 0** —— 这是本次新增的两条线。
- `.tmp` 主张的"离校 −2/年、废除地板"被**部分采纳**（离校 −2 采纳，废地板未采纳，改为"地板只管定时任务"）。
- 落点：`需求/01` §3.1–§3.4、`设计/02` §5。

## 3. 修心门 → ✅ 已裁决：**一次性 + 心性 ≥ 90 是突破判定条件**

**用户口径（r35）**：「修心是门是一次性的，现在的代码实现是有问题的。对于心性 ≥ 90 这个，是为了在突破的时候判定……如果心性 < 90，那么突破是必然失败的。」

- 入门判定**只做一次**（`heart.entered`）。
- 心性 ≥ 90 是**每一次突破判定的条件**，不是"每年重判的门"。
- **< 90 = 必然失败**（不是"概率很低"）。
- 已获得的品**不会因心性下降而退回**。
- 落点：`需求/11` §6.1–§6.2。

## 4. 灌顶 → ✅ 已裁决：**加大成功率，基本等于保送**

**用户口径（r35）**：「灌顶是加大量的成功率，基本等于保送进入。」

- 量级从 `+0.25` 提到 **+0.5 以上**（语义是"接近必过"）。
- 代价保留：钱财、心性 −6、欠人情、**该道下一扇门 −0.30**。
- 落点：`需求/11` §7.4。

## 5. 属性上限 → ✅ 已裁决：**要有，三层加法，满值可达 200**

**用户口径（r35）**：「属性上限这个肯定是要有的，要补充进来。」

- 出生 90 + 命格 30 + 事件 20 + 永久资源 15 + 临时 10 → clamp 200。
- **临时不进门槛判定**。
- 落点：`需求/01` §2.1。

## 6. 层级制 vs 修为条 → ✅ 已裁决：**互补的两道关**

**用户口径（r35）**：「层级制和修为条是互补的。现在修炼是先判断瓶颈（实际就是判断 lv 层级），lv 层级不破，那么就是入不了门槛的……瓶颈突破后，开始进入修炼，此时就是修为条判断，条满后又进入瓶颈判定。」

- 修正了新作的读取口径：**LV 层级是门，修为条是资格**，交替转。
- `.tmp` 那套"四道各一条 Lv 轨 + 境链"**没有复活**——它和现行的"品 + 瓶颈"是同一件事的不同写法，
  现行这套有代码有测试，继续用现行的。
- 落点：`需求/11` §1。
