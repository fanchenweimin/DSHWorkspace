# 需求 · 20 事件系统（回合、事件与常驻）

> 系统：**2x 事件系统**（游戏主进程，为修炼系统服务）
> 对应实现：`docs/设计/20-事件-流水线.md`
> **第 20 版重写**：一年拆成 12 个月；事件界面分**主要 / 常驻**两个模块；事件属性全部中文化（设计文档里才映射成英文字段）；求学从"随机事件"改为"常驻动作"；**出现概率改为批内权重（不是必出闸门）**；**主要事件可跨多年、常驻不超 1 年**；**强制事件封住常驻模块**。
> 本轮的口径来源：用户口述 + `proto/turn-proto.html`（回合制验证 v3 · 月制）。
> **r23 补了两条**：① 新增事件性质「**战事**」，战事由**日历**驱动（到点必来，不掷骰），详见 `21`；② 事件可以带**义务**（身份的年役），实现方式是强制事件，不新增机制。

---

## 1. 一句话

**事件系统不产修为，它决定"这一年你能做什么、什么时候必须停下来"。**

修炼系统给公式，事件系统给**顺序和代价**。同一份 12 个月，花在闭关上是修为，花在坊市上是钱，花在求学上是突破率——**这就是全部的取舍**。

---

## 2. 时间的单位是"月"

| 规则 | 内容 |
| --- | --- |
| 一年 | **12 个月**，年初归 12 |
| 货币 | **月**是唯一的时间货币，任何动作都标价多少月 |
| 不可存储 | 年末剩余月份**作废**，不结转、不可借、不可透支 |
| 最小单位 | 整月；超过 1 月的动作按整月扣，不足 1 月的向上取整 |
| 不可同时 | 同一时间只能做一件事；动作串行，按月扣 |
| 主要事件 | **可跨多年**：耗时写多少月就扣多少月（立相 12 月、闭死关 36 月），本年装不下就挂起，次年接着扣 |
| 常驻事件 | **不超过 1 年**：最多吃掉当年剩余月，不跨年；装不下就置灰，写明"还差 N 月" |
| 常驻 · 修炼（后期） | 寿元够长之后（建议 ≥ 200 岁）允许一次投入多年，最多 5 年——纯粹为了少点几十下 |
| 跨年期间 | 不能换动作，也**不会再冒出新事件**（你正在闭关/出征，外面找不到你） |

> **原型里有一个必须修掉的坑**：`qiBreakMonths` 在悟性 50 时返回 24 月，而一年只有 12 月，`S.time >= bt` 永远为假——**炼气 3 品以上的破境卡永远点不了**。要么把耗时压进 12 月，要么给破境开"跨年"。本轮选**跨年**（见 §4.3）。

## 3. 界面：两个模块，一个时间条

```
┌──────────── 本年时间 剩 7 月 ────────────┐
│ ▮▮▮▮▮▯▯▯▯▯▯▯   一月 … 十二月            │
└──────────────────────────────────────────┘

【主要事件】—— 事件系统筛出来的，会"找上门"
  ▸ 强制：军令出征            耗 4 月   ← 必须先处理
  ▸ 可选：山门大集            耗 2 月
  ▸ 可选：旧友来访            耗 1 月

【常驻事件】—— 永远在，不掷骰、不占池子
  ▸ 修炼·境界   ▸ 修炼·术法   ▸ 修炼·百艺
  ▸ 坊市(城中)  ▸ 委托(城中)  ▸ 求学(有瓶颈)
  ▸ 摆烂玩耍
```

| 模块 | 内容从哪来 | 玩家能不能不选 |
| --- | --- | --- |
| **主要事件** | 事件池筛选（四步入池 + 优先级批次 + 权重抽取） | **强制事件不能**；其他可以放着不管（**年末作废**） |
| **常驻事件**（次要） | 固定清单，按场景解锁（城内/瓶颈中/学籍） | **能**，但月份会白白流走 |

**两模块的关系**：没有强制事件时，主要事件是"额外的机会"，常驻事件才是玩家的主战场；**有强制事件时，常驻模块整体不可用**——军令在桌上，你别想安心修炼。

## 4. 主要事件怎么被筛出来（四步入池 + 两步上桌）

```
⓪ 日历注入   战事 / 主线节点按年份**直接塞进候选**（跳过 ①–④，不参与权重，见 `21` §2）
① 时间窗     年龄 / 学籍 / 身份 / 境界 / 场景，不符直接不入池
② 前置条件   标记、层级、修为、物品、关系（硬闸，不满足不入池）
③ 资格额度   一次性？冷却未到？本年次数用完？
④ 入池       过完 ①②③ 的全部进"本年候选"——这一步**不掷骰**
⑤ 优先级     取候选里优先级最小的一批
              ├─ 批内有强制 → 强制上第 1 槽
              └─ 批内无强制 → 批内按出现概率（权重）归一化抽一条
⑥ 上桌       主要事件区最多 3 槽（1 强制 + 2 可选）
```

**五条硬规则**：

0. **日历优先**：日历注入的事件直接上桌（`fromCalendar`），不与池内事件抢权重；同一天有多条时按 `order` 排。

1. **②和③必须分开**。②是"你有没有资格"，③是"今年轮不轮得到"。混在一起就会出现"修为满了但事件永远不来"。
2. **入池不掷骰，抽签只在上桌时做**。旧写法"每年年初给每条事件掷一次 10%~100% 的闸门"已经取消——它会让低档事件好几年见不到，也让"权重"失去了相对意义。
3. **抽走一条就重算一次批**，不是年初排完全年。
4. **可选事件错过就是错过**：年末候选直接清空，不补发、不结转。**不想让它错过，就把它设成强制事件。**

### 4.1 出现概率（1–10 档 = 权重，不是概率）

```
中签率 = 本条权重 ÷ 同批权重之和
例：同批五条，权重 1 / 2 / 3 / 4 / 5（和 = 15）
    第 1 条 1/15 ≈ 6.7%   第 5 条 5/15 ≈ 33.3%
```

| 同批权重 | 权重和 | 最低档中签 | 最高档中签 |
| --- | --- | --- | --- |
| 1 / 2 / 3 / 4 / 5 | 15 | 6.7% | 33.3% |
| 3 / 5 / 8 | 16 | 18.8% | 50.0% |
| 10（独自一批） | 10 | — | **100%** |

- **10 档不是必出**。它只在"这一批里只有它一条"时才是 100%。**所以要让一件事必上桌，用强制，不要用 10 档。**
- 档位只回答一个问题：**同批里谁更容易被先抽到**。它不代表"每年几成会来"。
- **抽走一条，剩余重算**：权重和变小，后面每条的相对份额都上升，所以候选不会"永远排在后面"。
- **权重管"先来后到"，稀有靠"冷却"**：真要让一件事几年一遇，用资格额度里的冷却年限，不要只把权重压到 1——月份够的时候，权重 1 也照样年年上桌。
- 强制事件**不参与加权**：批内有强制，直接占第 1 槽（多条强制时仍按权重抽一条，其余留到下个月）。
- 气运偏置：只对"机缘 / 灾祸"两类，`±(气运 − 50) × 0.002` 档（±0.1 档），改的是权重不是命中率。

### 4.2 优先级（1–5 档）

| 优先级 | 用在哪 | 例子 |
| --- | --- | --- |
| **1** | 生死 / 不可推 | 渡劫、被围剿、欠税劳役、军令出征、灭城之灾 |
| **2** | 瓶颈（有资格就必须出） | 立相、见众生、大心关、力破 / 散功 / 返本 |
| **3** | 主线节点 | 大考、入学判定、卒业分配、婚配、任职 |
| **4** | 人情与关系 | 师徒、同门、家族、官场、仇怨 |
| **5** | 日常与机缘 | 游历、小机缘、奇遇、闲事 |

**优先级是顺序，不是概率**：数值越小越先被看见，低优先级的事件**只能等高优先级那批清空**。**破境事件必须是优先级 2 且强制**——它不该跟"坊市买药"抢同一个骰子，也不该因为权重不够而迟到。

### 4.3 跨年：主要事件可以多年，常驻不超 1 年

| 类型 | 单次最长 | 跨年 | 说明 |
| --- | --- | --- | --- |
| **主要事件** | 不限（写多少月就是多少月） | **允许** | 立相 12 月、闭死关 36 月、远赴战场 18 月；本年装不下就挂起，次年接着扣，**期间不能换动作** |
| **常驻事件** | **12 月**（默认） | **不允许** | 坊市 1 月、委托 2–4 月、求学 3 月、修炼最多把当年剩余月用完 |
| **常驻 · 修炼**（后期） | 可多年 | 允许 | **寿元够长之后才解锁**（建议 ≥ 200 岁时开放，一次最多 5 年）；理由是"点几十下修炼太麻烦"，不是机制需要 |

> **为什么主要事件能多年、常驻不能**：主要事件是"命运找上门"，它本来就该长（闭关、出征、守孝）；常驻是"日常安排"，让它跨年等于玩家一年只做一个决定，月制的意义就没了。

## 5. 事件属性全表（这就是事件对象长什么样）

> 需求侧写中文，设计侧映射成英文字段（见 `设计/20` §1）。

| # | 属性 | 取值 | 干什么用 | 谁读它 |
| - | --- | --- | --- | --- |
| 1 | **事件标识** | 唯一字符串 | 存档引用、事件链引用、日志定位 | 存档 / 日志 |
| 2 | **事件名称** | 短句 | 卡片标题 | 界面 |
| 3 | **事件性质** | 8 类（见 §6） | **决定交给哪个系统结算**、放主要区还是常驻区、能不能被判失败 | 调度器 |
| 4 | **事件优先级** | 1–5 | 决定"谁先上桌"，取最小批 | 抽取器 |
| 5 | **是否强制** | 是 / 否 | 同批里优先返回；上桌后**必须先处理才能自由分配月份** | 抽取器 + 引擎 |
| 6 | **事件出现概率** | 1–10 档 | **同批内的抽取权重**（不是必出概率，也不是"每年几成会来"） | 抽取器 |
| 7 | **时间窗** | 年龄区间 / 学籍 / 身份 / 大境界 / 场景 | "这个年纪、这个身份会不会遇到" | 入池① |
| 8 | **前置条件** | 标记 / 层级 / 修为 / 物品 / 关系 | "遇到了能不能算数"（硬闸） | 入池② |
| 9 | **资格额度** | 一次性 / 冷却 N 年 / 每年 N 次 | "今年轮不轮得到" | 入池③ |
| 10 | **耗时** | 整数月（0 = 即时） | 扣多少个月；0 表示只做选择不花时间 | 引擎 |
| 11 | **可否跨年** | 是 / 否（主要事件默认是，常驻默认否） | 耗时 > 剩余月时，是挂起还是置灰；主要事件可多年，常驻最多 12 月 | 引擎 |
| 12 | **有效期** | N 月（默认到年末） | 超时未处理 = 错过，按"错过后果"结算 | 引擎 |
| 13 | **选项** | 1–4 个 | 每个选项自带：额外耗时 / 额外花费 / 判定 / 结果 | 界面 + 结算 |
| 14 | **判定方式** | 无 / 出现率 / 成功基数 / 属性对抗 / 境界压制 | 决定要不要掷骰、掷什么 | 结算 |
| 15 | **结果** | 数值写入清单 | 修为、属性、心性、气运、物品、身份、层级 | 结算 |
| 16 | **气运偏置** | 有 / 无（默认无） | 只对"机缘 / 灾祸"两类生效，改的是出现概率 ±0.1 档 | 入池④ |
| 17 | **事件链** | 链标识 + 序号 | 后续事件的前置；链断则后续全部作废 | 入池② |
| 18 | **场景标签** | 城中 / 野外 / 宗门 / 战场 | 与"坊市/委托只在城中"同一套判定 | 入池① |

### 5.1 五对最容易混淆的属性

| 容易混的 | 区别 |
| --- | --- |
| **事件出现概率** vs **瓶颈出现率 q** | q 是**修炼系统**的（管"这道墙挡不挡在你面前"，越高越难）；事件出现概率是**事件系统**的（管"这条事件今年来不来"，越高越常见）。**两者不互相替代**：q 高只说明墙在，门要不要开由事件管 |
| **事件优先级** vs **事件出现概率** | 优先级管**顺序**（谁先上桌），出现概率管**同批里的份额**（几条一起等的时候，谁更容易被抽中）。低优先级的事件，权重再高也得等前面那批清空 |
| **是否强制** vs **优先级 1** | 优先级 1 的事件几乎都强制，但"强制"是布尔开关：它可以出现在任何优先级（比如优先级 3 的大考也强制）。**强制 = 入池后直接占第 1 槽、不参与加权、处理完才能动别的事**；它来不来仍由时间窗与前置决定（前置不满足照样不入池） |
| **耗时** vs **有效期** | 耗时是"做它要几个月"，有效期是"这张卡几个月内有效"。即时事件（耗时 0）也可以有有效期 |
| **出现概率（权重）** vs **命中率** | 出现概率是**分子**，命中率是**归一化的结果**。同一档权重 3，同批和是 10 时命中 30%，和是 30 时只剩 10%——**档位不变，命中率随批次变**。所以不能把"10 档"读成"必出" |

## 6. 事件性质（7 类）

| 性质 | 作用 | 结算方 | 出现在 | 例子 |
| --- | --- | --- | --- | --- |
| **瓶颈** | 开门：把事件瓶颈放行，掷成功基数 | 修炼系统 | 主要 | 立相、见众生、大心关、力破 / 散功 / 返本 |
| **主线** | 推进学制、身份、人生节点 | 身份系统 | 主要 | 大考、入学判定、卒业分配、婚配 |
| **身份** | 职务带来的义务与收益 | 身份系统 | 主要 | 朝会、出征、赈灾、升迁 |
| **灾祸** | 减法：人口、财物、伤病、心性 | 事件系统 | 主要 | 天灾、战乱、劫修、瘟疫 |
| **机缘** | 加法：资源、功法、师承、秘境 | 事件系统 | 主要 | 奇遇、古洞、名师、宝药 |
| **日常** | 不带判定，只带数值或纯叙事 | 事件系统 | 主要（低优先） | 游历见闻、同门闲事 |
| **轮播** | 无选项，代表 N 年（长寿的时间感） | 引擎 | 不占槽 | "闭关三十载" |
| **战事** | 日历驱动的强制大事：城战、国战、征召 | 战斗系统 + 事件系统 | 主要（强制） | 北关城战、国战、军令 |

**性质决定它能不能被"推后"**：瓶颈、主线与战事会卡住进度，所以进主要区；日常不进常驻区（常驻是动作，不是叙事）。

**战事是唯一不掷骰的性质**：它由**日历**（`需求/21` §3）直接注入，到点必来，不看权重、不看气运。原因是战事必须是**世界事实**——所有人都在同一个年份遇到同一场战争，否则"运气差的人一辈子在打仗"。

### 6.1 义务：身份的年役

身份不是白拿的。每个身份带一条**年度义务**（`duty`）：军队每年 2–6 月戍守、宗门每年差役、朝廷每年朝会。

- 实现方式：**年初生成一个强制事件**，耗时几个月；不做新机制。
- 没履行：扣贡献、降身份（`需求/21` §7）。
- 这条就是"修炼不能只进不出"的机制版本——**身份越高，义务越重**。

---

### 6.5 一年只出**一件**主要事件（r30）

> **用户口径**：「一年只弹出一个主要事件就可以了，不用解决一个再出一个。」

- 处理掉那件主要事件之后，这一年**不再抽新的**（`turn.mainDone`），直到跨年。
- 剩下的月份照样可以修炼、学艺、逛坊市、闲居——**主事件是"今年的大事"，不是"必须一件接一件"**。
- 日历战事与事件瓶颈都算"大事"，同样占这一年。

## 7. 常驻事件（次要模块）全表

**常驻事件 = 动作。** 它们不掷骰、不进池、不被优先级管，只要条件满足就一直在。

| 常驻 | 出现条件 | 耗时 | 产出 | 说明 |
| --- | --- | --- | --- | --- |
| **修炼 · 境界** | 已入门、修为未满 | 当年剩余月（可指定 N 月，**上限 12**；寿元 ≥ 200 后可多年） | `修为 += 基数 × 0.2 × 月数` | 主产出；修为满了自动灰掉 |
| **修炼 · 术法** | 学过该术法 | N 月（上限 12） | `熟练 += 基数 × 0.2 ÷ 阶位系数 × 相性 × 月数` | 与境界**抢同一份月** |
| **修炼 · 百艺** | 有该门天赋或在学 | N 月（上限 12） | `积累 += 百艺基数 × 0.2 × 月数` | 同上 |
| **坊市** | **仅在城中** | 1 月 / 次 | 买卖、置换、打听消息 | 城外的"坊市"不出现 |
| **委托** | **仅在城中** | 2–4 月 / 单 | 钱、名声、人脉；可能有战斗 | 高风险单会写"可能受伤" |
| **求学** | **仅在"有瓶颈"时出现**（修为已满、q > 0、本年未破） | 3 月 / 次，每年最多 2 次 | 该品**成功基数 +0.03** | 封顶按学籍（§9） |
| **摆烂玩耍** | 永远 | 用尽剩余月（不跨年） | 无 | 让玩家把月用完，而不是被系统替他用完 |

**五条规则**：

1. **常驻不参与抽取**：它不会"没抽到"，也不会占主要事件的槽。
2. **常驻必须花月**：没有"顺手做"的常驻，否则时间就没有成本。
3. **常驻受场景限制**：坊市 / 委托写死"城中才有"——这是"进城"这件事的全部意义。
4. **常驻之间互斥**：一个月只能做一件事。
5. **常驻不跨年**（修炼后期例外）：常驻最多吃掉当年剩余月，装不下就置灰。**有强制事件未处理时，整个常驻模块不可用**（见 §10.2）。

## 8. 为什么"修炼"被拆成三个常驻

| 拆法 | 好处 | 代价 |
| --- | --- | --- |
| 合成一个"修炼"按钮 | 界面简单 | 玩家无法表达"这一年我练术法不练境界" |
| **拆成境界 / 术法 / 百艺三个**（本轮） | 取舍可见：三个都想要，但只有 12 个月 | 需要三套产出公式（已有） |

**这就是 `需求/10` §3.4 说的"抢同一份 12 个月"**。系统不惩罚你学得多，时间惩罚你。

## 9. 求学：从"随机事件"改成"常驻动作"

| | 旧（r17–r18） | 现在（r19） |
| --- | --- | --- |
| 形态 | 随机事件，优先级 4，每年最多 1 次 | **常驻动作**，有瓶颈才出现 |
| 触发 | 等它来 | 玩家自己点 |
| 代价 | 几乎为零（白拿 +0.03） | **3 个月**，每年最多 2 次 |
| 封顶 | ~~蒙 +0.06 / 府 +0.09 / 太 +0.15~~ | **改成按品：品 1–3 +0.06 / 品 4 +0.12**（与学籍脱钩，见 `11` §7）|
| 覆盖 | 蒙 锻 1–2｜府 锻 1–3 + 炼 1–3｜太 锻 1–4 + 炼 1–4 | 不变 |
| 门票 | 太学卒业才能触发"立相" | 不变（立相仍是事件瓶颈，求学只加基数） |

**为什么改**：旧写法里"求学"是白送的加成，玩家只能等运气；现在它明码标价——**这一年少练 3 个月，换这道墙宽 3 个点**。这才是取舍。

**它不解决事件瓶颈**：法相、养灵六门、品 5/6 必须等事件，求学只对**概率瓶颈**的成功基数生效（`需求/11` §4）。

## 10. 年度结算：年初一次，月内循环，年末清账

### 10.1 年初（自动，顺序写死）

```
① 寿元检查     年龄 +1；超过寿元 → 死
② 气运漂移     气运向 50 回归 ±1
③ 心性衰减     在册 −1 / 离校 −0.5；触地板 60 则 0
④ 心魔         心性 < 40 掷；< 20 必死
⑤ 城池层       人口回归 → 灾害修正 → 灵脉重算 → 席位 → 灵量分配
⑥ 跨年动作     先扣它的月（36 月的闭死关，今年先扣 12），剩下的才归玩家
⑦ 事件掷骰     按 §4 生成"本年候选"，排主要事件槽（**跨年期间不掷**）
```

**为什么城池层在事件之前**：今年的人口决定今年的灵脉，今年的灵脉决定今年的灵量，今年的灵量决定养灵者今年练多快——**事件是这一年的开头，不是结尾**。

### 10.2 月内（玩家驱动）

```
每个月：
  ├─ 有强制事件未处理 → 常驻模块整体置灰，只能处理强制事件（扣它的月）
  ├─ 否则 → 从主要事件 / 常驻事件里任选一个（扣它的月）
  └─ 月数归零 或 跨年动作挂起 → 进年末
```

**强制事件封住常驻**：这不是"建议"，是"这一年你别想安心修炼"。军令出征、灭城之灾都在这个层级——它们在桌上时，修炼、坊市、委托、求学、摆烂**全部灰掉**，并写明"有强制事件待处理"。

- **一年只能发起一次突破**（全局，不分道）——这条不变，但现在破境**要花月**，所以"什么时候破"本身也是取舍。
- 突破失败不扣修为，但**月份照扣**。

### 10.3 年末（自动）

```
① 未处理的可选事件 → 直接作废（错过就是错过，不结算、不补发、不结转）
② 剩余月份清零（不结转）
③ 突破/求学等本年额度复位
④ 跨年动作**不在这里推进**——它的月算在次年年初⑥，否则同一个月会被扣两次
```

**"错过"没有后果结算**——这是本轮的明确选择。想让一件事不能被忽略，就把它设成**强制事件**；可选事件的价值就在于"你可以不要它"。

### 10.4 城池层（每年一次，与角色层并列）

```
① 人口回归    人口 += clamp(基线 − 人口, −1万, +1万)
② 事件修正    天灾 −10 万 / 祥瑞 +2 万 / 战乱 −20 万
③ 灵脉重算    灵脉 = Σ 生灵灵量基数（修士 10 / 凡人 1 / 其他生灵 1）
④ 席位        席位满则不再新增；空席进"候选"
⑤ 灵量分配    决定今年把灵量分给谁（零和）
```

城池层不参与角色层判定，只产出三个数：**人口**（叙事）、**灵脉**（总量）、**灵量分配**（每个养灵者拿多少）。修心者不进这张账。

## 11. 心性、心魔、心关

| 机制 | 触发 | 判定 | 后果 |
| --- | --- | --- | --- |
| **心性衰减** | 每年（年初③） | 无 | −1 / −0.5，地板 60 停止 |
| **心魔** | 心性 < 40 | `0.10 × 心性 / 39` 存活 | 活：心性 −5、当前品修为清零；死：身死 |
| **心关** | 修心者每 5–10 年（事件） | `0.30 + 0.05 × (心性 − 90)` | 成功 `+30 × 心性/100` 道心；失败不给也不扣 |
| **大心关** | 道心满 + 层级够（事件） | 同上 | 破境；失败不扣道心 |

- **心魔是唯一的"内部死法"**，与战斗死亡并列。
- **修心没有月修为**：打坐不涨道心，道心只由心关事件推进。
- **心性窗口永不关闭**：跌破 90 只是"此后成功不给道心"，回补靠事件。
- 心魔不找凡人：锻体 < 3 品、炼气 < 2 品没有心魔。

## 12. 内容的最低要求（结构，不是文案）

| 类 | 每品至少 | 必须带 |
| --- | --- | --- |
| 瓶颈事件 | 22 个（锻 6 + 炼 6 + 养 6 + 修 4） | 一个基数、一个失败后果、一个"下次什么时候" |
| 主线事件 | 每段学制 5 | 时间窗 + 强制 + 错过后果 |
| 身份事件 | 每种身份 5 | 强制与收益各半 |
| 机缘 / 灾祸 | 各 20 | 出现概率档位 + 气运偏置 |
| 日常事件 | 不限 | 不带判定，只带数值或纯叙事 |
| 轮播事件 | 不限 | 无选项，代表 3–10 年 |
| 战事事件 | 每场战事 8–15 | 预警 1 + 每城 3–5 + 国战主线 5–8（见 `21` §9） |

**22 个瓶颈事件里，6 个是"单事件型"**（三个品 5 + 三个品 6 的单事件部分），只需写"事件到达即破境"，不写概率。三个品 6 各写一套（力破 / 散功 / 返本），不做事件链。

## 13. 与旧文档的差异（读旧文前先看这张表）

| 旧写法 | 现在 | 为什么 |
| --- | --- | --- |
| 一年一次结算，事件在年末抽 | **一年 12 月，事件在年初生成、月内消费** | 玩家要能选"这几个月干什么" |
| 事件只有一个列表 | **主要事件 + 常驻事件两个模块** | 常驻是动作，不是叙事，混在一起会让"修炼"看起来像随机事件 |
| 出现概率 = 每年通过率（档 × 10%） | **出现概率 = 同批权重**，归一化后才是命中率 | 一数两用会让低档事件几年见不到，也会让"10 档"被误读成必出 |
| 长动作一律置灰 | **主要事件可跨多年**，常驻不超 1 年 | 闭关、出征本来就该跨年；日常安排不该跨年 |
| 强制事件只是"排在最前" | **强制事件封住整个常驻模块** | 军令在桌上时还能安心修炼，强制就没有重量 |
| `priority` / `weight` / `threshold` 三个字段 | **优先级 + 出现概率（1–10）+ 是否强制** | 三个字段各管一件事，不再有"既当层级又当权重"的双轨 |
| 求学是随机事件（优先级 4） | **求学是常驻动作**（3 月 / +0.03 / 每年 2 次） | 白送的加成不是取舍 |
| 修炼在年度链第⑤步自动结算 | **修炼是常驻动作，玩家按月投入** | 时间成了货币 |
| 突破在年度链第⑥步自动判定 | **突破是动作，要花月，一年一次** | 同上；失败不扣修为但扣月 |
| 坊市 / 委托笼统写在"日常" | **写死"城中才有"** | 让"进城"有机制含义 |
| 战事是随机事件（碰运气） | **日历驱动，到点必来**（`21`） | 战事是世界事实，不是个人运气 |
| 身份只有收益 | **身份带年度义务**（§6.1） | 修炼不能只进不出 |
