### 1.1 难度曲线：指数上升（r23 规则，数值待重算）

```js
// 相邻两品的修为总量倍数：g 随品号递增，越往后越陡
const TIER_G = [null, 1.6, 2.0, 2.2, 2.4, 2.6];   // g[n] = PROF[n] / PROF[n-1] 的下限

// 加载期断言：曲线必须真的是指数，不是斜坡
function assertIndexCurve(PROF) {
  for (const dao of ['body', 'qi', 'spirit']) {
    for (let n = 1; n < PROF[dao].length; n++) {
      const g = PROF[dao][n] / PROF[dao][n - 1];
      if (g < TIER_G[n]) throw new Error(`${dao}[${n}] 倍数 ${g.toFixed(2)} < 下限 ${TIER_G[n]}`);
    }
  }
}
```

**为什么写成断言而不是"写进文档提醒一下"**：曲线一旦退化成线性，玩家体感是"每品都差不多"，前三品与第四品没有落差；而这件事在数值表里只体现为几个比值，**肉眼看不出来**。所以让它在启动时炸掉。

**当前表不满足这条**（这是 r23 明确留下的债）：

| 段 | 现倍数 | 下限 | 判定 |
| --- | --- | --- | --- |
| 锻 1→2 | 2.21 | 1.6 | 通过 |
| 锻 2→3 | 5.16 | 2.0 | 通过（过陡，r23 会压） |
| 锻 3→4 | **1.56** | 2.2 | **不通过** |
| 锻 4→5 | **1.56** | 2.4 | **不通过** |
| 锻 5→6 | **1.46** | 2.6 | **不通过** |
| 炼 1→2 | 3.33 | 1.6 | 通过（过陡） |
| 炼 2→3 | 3.00 | 2.0 | 通过（过陡） |
| 炼 3→4 | 2.00 | 2.2 | **不通过** |
| 炼 4→5 | **1.56** | 2.4 | **不通过** |
| 炼 5→6 | **1.43** | 2.6 | **不通过** |

**读法**：现在的表是"前两品极陡、后面变平"——正好和"越往后越难"相反。之所以长成这样，是因为它被两个锚点（10 岁到脏腑、30 岁脱凡）反向凑出来，**凑的时候只看了年龄，没看曲线形状**。r23 重排时，两个锚点仍然必须守住，所以要同步放松 `b` / `q` / 求学 / 丹药，而不是改锚点。

### 1.2 成就线：第四品

```js
const MILESTONE = 4;   // 某道 ≥ 4 品，才算"在这一道上有了成就"
```

**这一格是三个系统的共同门槛**，不是文案：

| 用到的地方 | 判定 |
| --- | --- |
| 任事（军队/宗门/朝廷职务） | `level >= MILESTONE` |
| 认知障·自悟（三种入场券之一） | `body.level >= 4 && qi.level >= 4` |
| 事件门槛（"请一位四品出手"） | `{"realm":{"dao":"qi","gte":4}}` |

**三人成虎的写法要避免**：不要在三个地方各写一个 `4`，只写 `MILESTONE`。如果哪天要改成"五品才算"，改一个常量，所有门槛一起动。

### 1.3 认知障：养灵的入场券，不是养灵本身

**三条等价入口，任一即可**；它们都只回答"这个人有没有资格去敲养灵的门"，**不产生 `spirit.level`**：

```js
// 三条入场券（软）：任一为真，`cognition.spirit = true`
function cognitionOpen(S) {
  return (S.path.body.level >= 4 && S.path.qi.level >= 4)   // ① 自悟
      || S.flag['edu.graduated'] === true                    // ② 太学卒业
      || S.flag['spirit.guide'] === true;                    // ③ 师承引路
}

// 有资格敲门：禀赋 + 入场券
function canKnockSpirit(S) {
  return S.attr.aptitude.eff >= 80 && S.attr.insight.eff >= 80 && cognitionOpen(S);
}

// 真正的门：`spirit.level` 只有事件判定能写（§8.1 见众生）
// 注意：canKnockSpirit 为真 ≠ 已入养灵；Lv0 仍然是 Lv0
```

**判据（写进断言）**：`spirit.level` 的**唯一写入点**是 `commit(S,'spirit',1)`（见众生判定成功）。任何 `mod` / `set` / 事件效果都**不许**直接写 `path.spirit.level`，否则"入场券"就变成了"境界"——这是 I25。

**为什么要分这么细**：三条路都只是"知道灵是什么"。真正进门那一下，仍然要在六道门上过——**资质 80 的人也可能一辈子停在 Lv0**。这就是"双四品不等于养灵"的代码版本。

## 2. 四条独立路线 + 一条螺旋（r23）

### 2.1 机制：四条进度条，四个投料口

```text
path.body   内力 ─┐
path.qi     法力 ─┤  四条独立进度条，互不相通（I2）
path.spirit 灵力 ─┤  每个月的修炼必须指定一条
path.heart  道心 ─┘  修心不吃月修为（只吃心关事件）
```

**修炼动作带 `dao` 参数**，这是 r23 最重要的一行接口变更：

```js
function trainMonth(S, dao, months) {
  const got = monthGain(S, dao) * months;      // 基数 × 0.20 × 乘区
  S.path[dao].bar += got;
  spill(S, dao, got);                          // §7 ①：外溢给低阶同品号
  return got;
}
```

- **不指定 `dao` 的调用是 bug**：旧接口 `trainMonth(S, months)` 会隐式"喂下一个该修的境界"，那正是 r22 把四条路线压成一条梯子的地方。
- **`heart` 例外**：`trainMonth(S,'heart')` 直接报错，道心只由心关事件推进（I4）。
- **一年一次突破仍然全局**（I9）：四道都满了，也只能挑一道试。

### 2.2 螺旋：默认策略，不是硬规则

引擎里**没有**"必须先修锻体"这条规则。但外溢与拆墙（§7）合起来，会让某一种顺序明显更快，于是它变成了社会共识：

```js
// 只用于：人口模型、新手引导、NPC 默认行为。不是校验，不拦人。
function nextSuggested(S) {
  const spiral = [
    ['body', 1], ['body', 2], ['qi', 1], ['qi', 2],
    ['qi', 3], ['qi', 4], ['body', 3], ['body', 4]
  ];
  for (const [dao, tier] of spiral) if (S.path[dao].level < tier) return dao;
  return 'spirit';
}
```

| 顺序 | 为什么在这一点上 |
| --- | --- |
| 体魄 → 脏腑 | 锻体前两品最便宜（合计 450 点），先把"肉身"垫起来 |
| 感气 → 破胎 | 破胎才开始换命（寿元仍不变），也是太学门票 |
| 驭凡 → 法相 | 法相要"立相"，需要太学 + 一次判定，是炼气的分水岭 |
| **锻 3/4 排在后面** | 它们由炼气 3/4 **外溢**，不用亲手修；等炼气推不动了再回来补 |

**为什么不把螺旋写进 `rules/`**：写进去就变成"只有一种玩法"。现在的写法允许玩家把 30 个月全砸在锻体上——他只是会发现炼气一片空白、养灵永远进不去（§2.2 的认知门槛），**这是惩罚，不是禁止**。

### 2.3 凡人 / 脱凡 / 成就，三个不同的线

| 线 | 判定 | 含义 |
| --- | --- | --- |
| **凡人** | `body.level < 3 && qi.level < 2` | 没跨过破胎，寿元也是凡人 |
| **脱凡** | `qi.level >= 2` | 破胎，能当兵、能进太学 |
| **有成** | `任意一道 level >= MILESTONE(4)` | 能任事、能碰养灵 |

**三条线不重叠**，这是人口统计必须分开报的原因：r22 只报了"脱凡 90%"，但没报"有成"有多少——按旧曲线，30 岁到四品的比例远低于 90%。

## 4. 表一：瓶颈出现率（修为满了，墙出不出来）

**`q = 0`**：这一品对这个人**没有墙**——修为满了当年直接破，不吃首次必败、不耗年份、不占"一年一次"额度。

### 4.1 r22 新增：墙**只掷一次**

`q` 在这一品**第一次修为满时**掷一次，掷中（墙出现）就一直挡着，直到过去；掷不中（没有墙）当场就破。

**r21 的做法是每年重掷，这是错的**：以破胎为例，`q = 70%` 意味着每年有 30% 概率"今年没墙、白送一次"。连掷 15 年，`1 − 0.7^15 ≈ 99.5%` 的人至少白捡一次，那道墙等于不存在——r21 的 30 岁 91% 里，有很大一块是这么来的，而不是"磨过去"的。

**改成只掷一次之后**，`q` 才回到它该有的含义：**这一品对这个人有没有墙**。有墙的人只能靠 §6 的三项加成一年一年磨；没墙的人是命好，当年就过。

## 5. 表二：突破成功基数（墙出现了，门有多宽）

### 5.1 概率瓶颈（r22 改式）

```text
b = max(0, 属性 − 40) × 0.0030
  资质/悟性 44 → 1.2%    50 → 3.0%    60 → 6.0%    70 → 9.0%    78 → 11.4%
```

**为什么从 `属性 × 0.0012` 改成"零点式"**：等比式下 44 与 78 只差 1.8 倍（5.3% vs 9.4%），加上求学 6% 与累积 3% 的固定项后，两端几乎拉平——实测 30 岁脱凡率在 44–48 段 83%、65+ 段 93%，只差 10 个点，**天赋几乎不影响命运**。
改成"减 40 再乘"后，低天赋的 `b` 掉到 1–3%，高天赋到 11%，两端在 30 岁这条线上差出 20 个点以上（§9.2）。这也符合直觉：**40 以下是"没有修行资质"，不是"资质差一点"**。

### 5.2 事件瓶颈（本轮不动）

```text
炼气·法相      b = 0.10 + max(0, 悟性 − 89) × 0.01        → 90: 11%，100: 21%
养灵 Lv1–6     b = 0.35 + max(0, 资质 + 悟性 − 160) × 0.01 → 双80: 35%，双90: 55%
修心 Lv1–4     b = 0.30 + max(0, 心性 − 90) × 0.05         → 90: 30%，100: 80%
品 6 三关      见 §8.3（三套各不相同）
品 5 三关      不掷骰（event_once）
```

> 事件瓶颈的基数与概率瓶颈**不同尺度**是有意的：概率瓶颈一年一次、可以磨十几年；事件瓶颈要等事件（5–66 年一次），所以门必须宽。

## 6. 概率瓶颈：完整算法

```text
p = clamp(b + 求学 + 累积 + 嗑药 + 气运, 0, 0.95)
```

| 项 | 值 | 上限 |
| --- | --- | --- |
| `b` | `max(0, 属性 − 40) × 0.0030`（§5.1） | — |
| **求学** | 每次 +0.03（**3 月/次，每年 2 次**）；按品累积 | 品1–2 **+0.06** / 品3 **+0.06** / 品4 **+0.12** |
| **累积（失败补偿）** | 首次失败 +0.02；之后每次 `+U(0.01, 0.03)` | **+0.10**（同品，成功/跨品清零） |
| **嗑药** | 固本丹 +0.05 / 喂招 +0.08（均当年有效） | 合计 **+0.13** |
| 气运 | `clamp((luck − 50) × 0.001, −0.05, +0.05)` | ±0.05 |

> **r35 改**：累积上限从 **0.03 → 0.10**（用户口径：「失败后叠加成功率……不能超过 0.1，
> 基础 0.05、失败一次加 0.03，那么失败 10 次和 50 次都是 0.05+0.1=0.15」）。
> **这条上限是全局的、硬的**：不管失败多少次，累积项最多贡献 0.1。
> 理由：没有上限，"磨"就是唯一解，求学/丹药/气运/灌顶全部失去意义。

**量级对照（资质 55、嗑齐药、求学封顶、累积触顶）**：

```text
b      = (55 − 40) × 0.003 = 0.045
求学    = 0.06
累积    = 0.10   ← r35：触顶值（原来是 0.03）
嗑药    = 0.13
气运    = ±0.05
────────────────────────
p ≈ 0.335   （原口径 0.265）
```

> ⚠️ **数值全部待重推**（`PROGRESS.md` §0）。这里只固定**上限口径 = 0.10** 与**加法结构**，
> `b` 的系数、求学 0.03、嗑药 0.13、气运 ±0.05 都会在重推那一轮一起动。

**没药的人**（`b 0.045 + 累积 0.1` ≈ 0.145）→ 平均 7 年。**这就是"嗑药"的全部含义**——
它不改变"能不能过"，只改变"几年过"。

### 6.1 尝试节奏

- **每年一次**（角色层 step6），**全局一年只能发起一次突破**（不论哪道哪品）。
- 前置：修为条满 + 层级 = 品 − 1。
- 顺序：先看**墙在不在**（§4.1，一品只掷一次）→ 没墙即破；有墙 → 掷 `p`。
- **首次必败**：`attempts === 0` 时直接判失败（等价于 `b` 第一次不生效）。
- 失败：**不扣修为、不掉层级、不清修为条**，只损失这一年。

### 6.1 修为条的语义（r28 修正）

**`PROF[dao][n-1]` = 站在第 n 品上、练到能破下一品所需的修为。**

| 层级 | 修为条上限 | 说明 |
| --- | --- | --- |
| 0（还没入品） | **null** | 没有条。入品只看瓶颈，开局由 `systems/opening.js` 判一次 |
| 1（体魄） | `PROF[0]` = 140 | 练满 140 才有资格破脏腑 |
| n | `PROF[n-1]` | 同上 |
| 最高品 | **null** | 没有下一品，不再有可修的东西 |
| 修心（累计制） | `PROF[level]` | 道心不清零，四个值就是四道门槛本身 |

> 这条以前写错了一格（`PROF[level]`），结果"未入门"那一档也长出一条进度条，
> 而且每品的修为都提前用掉了一格。r28 改回归档里的定义：
> 「练满才有资格破下一品」——所以修为条属于**当前站着的这一品**。

### 6.2 伪代码

```js
function attempt(state, dao, tier) {
  const S = state, path = S.path[dao];
  if (S.turn.breakthroughUsed)      return fail('one_per_year');
  if (path.level >= tier)           return fail('already');
  if (path.level < tier - 1)        return fail('level_gap');

  // r30：事件瓶颈只能由事件开。force=true 表示"那件事办成了"，直接进品、不再掷骰
  const kind = bottleneckOf(dao, tier);
  const force = params.force === true;
  if (kind !== 'prob' && !force)    return fail('need_event');
  if (force) { commit(S, dao, tier); return ok('event'); }
  // r28：这里**不查修为条**。
  //   ① 入门关（第 1 品）根本没有条，只看瓶颈；
  //   ② 品内的"修为得先练满"是**资格**，放在业务层（turn.breakAct）拦，好给出"还差多少"。

  S.turn.breakthroughUsed = true;

  // ① 墙出不出现：**本品的墙只掷一次**，结果缓存在 path.wall[tier]
  if (path.wall[tier] === undefined) path.wall[tier] = Math.random() < appearRate(S, dao, tier);  // 键=品号
  if (!path.wall[tier]) { commit(S, dao, tier); return ok('no_wall'); }

  // ② 门有多宽
  const entry = tier === 1;                    // 入门关：不吃"首次必败"，基数有下限
  path.attempts += 1;
  if (!entry && path.attempts === 1) { path.fail = 0.02; return fail('first_try'); }

  const base = entry ? Math.max(successBase(S, dao, tier), S.openBase ?? 0.25)
                     : successBase(S, dao, tier);
  const p = Math.min(0.95, base + (entry ? 0 : studyBonus(S, dao, tier))
                          + path.fail + pillBonus(S, dao, tier) + luckAdj(S));
  const roll = Math.random();
  if (roll < p) { commit(S, dao, tier); return ok('roll', { p, roll }); }
  path.fail = Math.min(0.10, path.fail + 0.01 + Math.random() * 0.02);   // r35：上限 0.10
  return fail('roll', { p, roll });
}

// commit(S, dao, tier) 见 §7.4：记层级 → 清条 → 清失败 → 作废本品墙 → 拆低阶墙
```

> `path.wall` 是 r22 新增字段（**以品号为键**：`{ '2': true }`；无键 = 未掷，`false` = 无墙，`true` = 墙在），必须**存档**——否则读档能刷墙。

## 7. 带动：外溢 + 拆墙（r23 重定义）

**作废两条旧写法**：r17–r21 的「大境界互补」（出现率 ×0.1 / 事件基数 ×10）、r22 的「自动补齐」（`level = N`）。前者是乘法、后者是跳级，都不是用户要的"高境界修炼会给低境界带来好处"。

### 7.1 两条机制

```text
① 外溢 spill      修 阶 M 的道时，对每一条 阶 < M 的同品号（品 ≥ 2）：
                      bar += 本月所得 × SPILL_RATE(0.10)
                      已满则丢弃（不结转、不折、不换道）

② 拆墙 breakWall  在 阶 M 达成第 N 品（N ≥ 2）时，对每一条 阶 < M 的第 N 品：
                      wall[N] = false        // 等价于 q = 0
                      若该品已过 → 无动作
```

```js
const RANK = { body: 1, qi: 2, spirit: 3 };
const SPILL_RATE = 0.10;

function spill(S, dao, gained) {
  const m = RANK[dao];
  for (const lo of Object.keys(RANK)) {
    if (RANK[lo] >= m) continue;                         // 只从高到低
    const p = S.path[lo];
    const tier = Math.min(p.level + 1, PROF[lo].length);  // 同品号 = 下一品
    if (tier < 2) continue;                              // 品 1 不带
    if (p.bar >= PROF[lo][tier - 1]) continue;           // 已满，丢弃
    p.bar = Math.min(PROF[lo][tier - 1], p.bar + gained * SPILL_RATE);
  }
}

function breakWall(S, dao, tier) {
  if (tier < 2) return;                                  // 品 1 不带
  const m = RANK[dao];
  for (const lo of Object.keys(RANK)) {
    if (RANK[lo] >= m) continue;
    if (S.path[lo].level < tier) S.path[lo].wall[tier] = false;  // 墙直接判"不存在"
  }
}
```

**`spill` 的"同品号"取的是 `p.level + 1`**：低阶那道正卡在第 N 品上，就是"同品号"。所以外溢只会推进**正在撞的那一格**，不会把整条低阶路线填满。

### 7.2 外溢率为什么是 10%

| 值 | 效果 | 结论 |
| --- | --- | --- |
| 0 | 四条路线完全独立，玩家前 40 年全在补底子 | 太苦 |
| **0.10** | 修 10 个月炼气 ≈ 给锻体 1 个月 | **默认**：补得动，但不会白送 |
| 0.30 | 修 3 个月抵 1 个月，锻体几乎不用亲手修 | 低阶失去重量 |
| 1.00 | 等价于"一条梯子"（r22） | 作废 |

**外溢率是常量，不是公式**：它属于"手感调节"，进 `rules/prof.js` 的常量表，不进 `data/`（策划改不了，避免有人把它当平衡旋钮乱调）。

### 7.3 拆墙与"首次必败"的关系

拆墙只把 `q` 判成 0，**不清 `attempts`、不改 `fail`**：

- 若这一品**从没试过** → 拆墙后下一次冲关直接 `no_wall`，当年就过（不占"首次必败"）。
- 若这一品**已经试过并失败过** → 拆墙后仍然要掷一次 `p`（因为"这一年"的时间已经花掉了），但 `q` 不再挡路。

**这条差别很重要**：它让"先修高阶再回头补"比"一开始死磕低阶"更划算，但不是免费——**已经交过的学费不退**。

### 7.4 四条边界

1. **品 1 不带**：没有更低一阶的同品号可带。
2. **只补同品号**：破胎带脏腑，不带调息。
3. **只从高到低**：`RANK` 单向，锻体不给炼气任何东西。
4. **不给层级、不占额度、不掷骰**：外溢只加 `bar`，拆墙只写 `wall[N]=false`。

```js
// 破境成功后统一调用（顺序：先记层级，再拆墙）
function commit(S, dao, tier) {
  const path = S.path[dao];
  path.level = tier;
  if (dao !== 'heart') path.bar = 0;
  path.fail = 0; path.attempts = 0;
  path.wall[tier] = undefined;
  clearStudyBonus(S, dao, tier);
  breakWall(S, dao, tier);        // §7 ②
}
```

> **存档影响**：`wall` 现在会出现"被外部写成 `false`"的键，读档必须原样恢复；`spill` 不产生新字段，只改 `bar`。

## 10. 边界与断言

| 场景 | 期望 |
| --- | --- |
| `q = 0`（这一品没有墙） | 当年直接破，不吃首次必败、不耗年份、不占额度 |
| 同一品的墙掷过一次 | 之后每年**不再重掷** `q`，只掷 `p`（读档也不能刷） |
| 概率瓶颈第一次尝试 | 必失败，且 `fail = 0.02` |
| **`fail` 达到 0.10** | **不再增长**（r35：原为 0.03）；失败 10 次与 50 次结果相同 |
| `p` 算出来 > 0.95 | 钳 0.95 |
| 事件瓶颈失败 | 修为条**不变**、层级不变、只损失这一年 |
| 同一年第二次尝试 | `one_per_year`，直接拒绝（`force` 与入门关除外，见 r35 待修） |
| 跨大境界拿层级 | 禁止（`level_gap`） |
| **修心突破且心性 < 90** | **必然失败**（不进品、不掷骰），`why = 'heart_low'` |
| **修心入门已通过后心性掉到 89** | **已获得的品不退回**；只是推不动下一品 |
| 修炼气 10 月，锻体 2 品未满 | `path.body.bar += 炼气月所得 × 0.10`；**不产生层级** |
| 炼气到 2 品 | `path.body.wall[2] = false`；**锻体 2 品层级不变**（修为还要自己修满） |
| 拆墙后再冲关 | 直接 `no_wall` 当年破；若此前已试过并失败，仍要掷一次 `p` |
| 已过品被拆墙 | 无动作（`level >= tier` 时不写 `wall`） |
| 品 1 | 外溢与拆墙都不发生 |
| 修心成功破境 | `bar` **不清零**（累计制） |

## 11. 与 r21 的差异（读旧设计前先看这张表）

| 项 | r21 | r22 | 为什么 |
| --- | --- | --- | --- |
| 结构 | 锻体 / 炼气**两条可选职业**（75/25） | **一条梯子**（体魄→脏腑→感气→破胎） | 用户：修炼以更高大境界为主 |
