## 2. 架构分层

```text
浏览器
  ├─ index/login/admin 页  ──► 静态文件（server.js serveStatic）
  └─ game.js ──fetch──► /api/runs/:id/...  ──► server.js handleApi
                                                  │
                                     ┌────────────┴─────────────┐
                                     │                          │
                              src/game/engine.js          src/db.js
                              （纯函数 + 可变 state）      （SQLite 持久化）
                                     │
                              src/game/content.js
                              src/game/defaultConfig.js
```

**关键约定**

1. `engine.js` 不碰 HTTP、不碰 SQLite。它接收一个 `state` 对象，就地修改，返回同一个对象；错误统一抛 `GameError(code, message, status)`。
2. `server.js` 负责：读包 → 载入 state → 校验 `rev` → 调 engine → 存盘 → 只向前端返回 `publicState()`。
3. **隐藏信息边界**：`publicState()` 绝不包含 `hidden`（资质/悟性/心性/气运/百艺天资）、`lifespan`、`omens`。只有 `GET /api/runs/:id/hidden`（sysadmin）返回 `hiddenState()`。
4. 每次状态变更都 `bumpRev()`，前端带 `rev` 回传；不一致返回 `409 STALE`，防止双开覆盖。

## 3. 数据模型

### 3.1 SQLite 表（`src/db.js`）

```sql
users(id, username UNIQUE, password_hash, role, created_at)
sessions(token_hash PK, user_id FK, expires_at, created_at)
runs(id PK, user_id, name, state_json, age, realm_line, phase, ended, created_at, updated_at)
game_config(id=1, config_json, updated_at)
```

- 密码：`scrypt(password, salt, 64)`，存 `salt:hex`。
- 会话：随机 32 字节令牌，**只存 SHA-256**；Cookie `dayao_session`，HttpOnly + SameSite=Lax，7 天。
- 存档：**整局 state 序列化进 `state_json`**，`age/realm_line/phase/ended` 只是列表用的冗余列。
- 配置：全库只有一行（`id=1`）。新开局时把当时的配置**深拷贝进 `state.config`**（快照），之后管理员改配置不影响旧档。

### 3.2 单局 state（内存结构）

```js
{
  version: 2, id, name, createdAt,
  config, configVersion,          // 开局时的境界配置快照
  age, lifespan, turn, rev, phase, // phase: event|result|bottleneck|battle|ended
  education: {
    stage,                        // 蒙学|府学|太学|卒业|肄业
    study,                        // 课业，影响太学大考
    examAttempts, passed, lastExamAge, enteredAt,
    reentry,                      // 是否以「太学进修」身份回归
    missedExam, craftChosen, craft
  },
  realms: {                       // 每个大境界一份
    [key]: { stageIndex, prof, unlocked, blocked, awaiting, completed, attempts }
  },
  activeRealm,                    // 唯一主修
  hidden: { aptitude, insight, heart, luck, baseLuck, caps, heartDecay, craftTalents },
  origin: [{label, text}],        // 七岁前三段出身
  methods: { [realmKey]: methodId },
  arts:    { [realmKey]: [artId] },
  mastery: { [methodId]: 0-100 },
  equipment: { weapon },
  items:   { money: 铜, [itemId]: count },
  skills:  { alchemy, forging, talisman, formation },   // 0-5
  flags:   { ... },               // 剧情标记，见 3.3
  merit, worldRecognition, trueDao,
  currentEventId, tasks, seenEvents, lastEventId,
  result, bottleneck, battle, ending, pendingEnding,
  journal: [{ age, title, text }]
}
```

## 4. 核心循环（状态机）

```text
            choose()
  event ──────────────► result ──continueRun()──► event（下一幕）
    │                     │
    │ battle 分支          └─► bottleneck（若本回合触发瓶颈，result 带 isBottleneck）
    ▼
  battle ──finishBattle()──► result
                              │
                     pendingEnding / 寿数到 ──► ended
```

- `choose()`：校验 phase/choice 可用性 → `evaluateCheck()` → 取 success/failure 分支 → 应用 effects → `advanceAge()` → `applySchoolPassive()` → `resolveAwaiting()` → `processProgression()` → `makeResult()`。
- `advanceAge()` 内部还会：触发 `applyMilestones()`（学制、境界解锁）、累加 `heartDecay`（每 3 年心性 -1）。
- `processProgression()` 只在 `prof >= 100` 时推进；失败则 `openBottleneck()` 进入 `bottleneck` 阶段。
- 结局：`pendingEnding`（战死/走火入魔/寿终）或 `abandonRun()`（归隐）→ `buildEnding()` → `phase='ended'`。

## 5. 境界系统（改造重点区）

### 5.1 配置结构（`defaultConfig.js`）

```js
{
  version, recognitionLabel: '世界认可', daoLabel: '悟道',
  realms: [{
    key, name, seal, order,
    attribute: 'aptitude'|'insight'|'heart'|'aptitude_insight'|'balanced',
    unlock: 'start'|'age11'|'tai_gate'|'heart_gate',
    accent, soft, school, description,
    stages: [{
      name, description,
      breakthrough: { type, difficulty, allowPills, note }
    }]
  }]
}
```

- `type`：`normal`（入门，可用丹药）、`effort`（大成）、`world`（圆满，需世界认可）、`dao`（大圆满，需悟道）、`heart`（心关）。
- 当前四道：锻体（资质）、炼气（悟性）、养灵（资质+悟性）、修心（心性）。

### 5.2 关键函数（`engine.js`）

| 函数 | 行（基线） | 职责 |
| --- | --- | --- |
| `realmAttributeKeys(cfg)` / `realmAttribute(state,key)` | 748 / 758 | 配置里的 attribute → 实际隐藏属性取值 |
| `methodFactor(state,key)` | 143 | 功法品级 + 熟练度 → 修炼倍率（无功法 0.2） |
| `applyTraining(state,key,base,...)` | 802 | **单次修炼收益**：`base × 主修权重 × 功法 × hiddenFactor × 随机` |
| `naturalChance(state,key,targetIndex)` | 1084 | 修为满时**自然突破**概率：`42 + attr*0.5 + luck*0.12 - difficulty*0.55 + 熟练*0.08`，effort -9，heart -12，无功法 -8 |
| `processProgression` | 1124 | 遍历四道，满 100 则判定推进 / 挂起（world/dao）/ 开瓶颈 |
| `openBottleneck` | 1162 | 把 `realm.blocked=true`，切 `phase='bottleneck'` |
| `bottleneckMethods(state)` | 1789 | **按类型/大境界生成破境手段列表**（当前所有类型都可反复尝试） |
| `resolveBottleneck` | 1878 | 掷骰，成功推进，失败 `attempts+1` 并回 result（下次 `attempts*6` 加成） |
| `resolveAwaiting` | 1071 | world/dao 挂起项在拿到认可/悟道后自动开 |
| `checkUnlocks` | 1022 | 养灵、修心的动态解锁 |
| `applyMilestones` | 973 | 11 岁入府学（解锁炼气 + 发功法）、15 岁后未考则肄业、20 岁卒业 |
| `evaluateCheck(state,check)` | 1210 | 事件判定：`50 + (attr - difficulty) + luck*0.35 + 境界*2 + 熟练*0.08` |

### 5.3 当前行为（与目标规则的差距）

| 规则 | 现状 | 差距 |
| --- | --- | --- |
| 锻体·资质越高修炼越快 | `hiddenFactor = 0.8 + attr/150`，资质 40→1.07、90→1.40 | 有，但幅度弱、不直观 |
| 锻体前三重资质高不易瓶颈 | `naturalChance` 含 `attr*0.5` | 有倾向，但无明确阈值语义，且失败可无限重试 |
| 第四重必有机缘、不能靠重试 | `effort` 型可用「闭关/游历/论道」反复尝试，每次 +6 | **不符合**，需改为机缘驱动 |
| 炼气不能用普通丹药 | 前三重 `allowPills: true`，瓶颈手段含「借药引气」 | **不符合** |
| 炼气可用短期提升悟性的宝贝 / 宝地历练 | 无 | **缺失** |
| 炼气第四重需明悟；资质不足可请高人灌顶（限上限） | 无灌顶机制 | **缺失** |
| 养灵不能靠外力，只能机缘 | 前三重 `allowPills: true`，可用灵草 | **不符合** |
| 修心非明心见性不可入；化凡可能跌落/走火入魔；心魔九死一生 | 化凡稳定 +42 修为，心魔失败只扣气运 | **不符合** |
| 入府学 ≠ 能感气 | 11 岁 `applyMilestones` 直接解锁炼气并发功法 | **不符合** |
| 太学只教「养灵是什么」 | 太学直接发 `spirit_school` 功法 | 部分符合（功法有，但门槛过松） |
| 锻体+炼气均至第四重才有资格感悟生命本质 | 现为 `body>=4 || qi>=4 || life_understanding` | **不符合**（应为「且」，且是资格而非直接解锁） |
| 世界认可需先有一道修至第四小境界圆满 | `save_city`(25+)、`legacy`(55+)、北狄祭司 随时可给 | **不符合** |
| 心性不是道德值 | 大量「行善/救人」直接 +心性 | **不符合**，需重定义与全量内容审计 |

### 5.4 心性（`hidden.heart`）

- 现状语义混用：助人、孝顺、救孩子都 +心性；`advanceAge` 每 3 年 -1；大彻大悟 +10 并 `raiseCap`。
- 目标语义（用户口径）：**心性 = 对自我的确信程度**，不是善恶。魔头不自疑 → 心性高；摇摆、怀疑自我 → 心性低。
- 影响点：修心解锁（`HEART_GATE=75`）、`evaluateCheck({stat:'heart'})`、部分事件分支。

## 6. 事件系统（`content.js` + `drawNextEvent`）

### 6.1 事件结构

```js
{
  id, icon, title, kicker, body,
  minAge, maxAge, education: ['府学',...],
  once: true | repeatable: true, weight,
  requires: { flags: {...}, stage: { body: 3 } },
  minStage / anyStage,
  special: 'exam' | 'craft_choice',
  dynamicChoices: 'cultivate',
  choices: [{
    id, label, hint, tags, time,
    requires: { money, items, stage, education, flags, skill },
    check: { stat, difficulty, label },
    success: { text, effects, battle },
    failure: { text, effects },
    effects, text, special, skill
  }]
}
```

### 6.2 抽取流程（`drawNextEvent`，行 687）

1. `pendingEnding` / 寿数到 → 直接结束。
2. `needsExam()`（15 岁、府学、未考）→ **强制**太学大考。
3. `forcedEventFor()` → 强制事件链：`craft_path`（府学未选百艺）→ `life_chain`（有 `near_death`）→ `great_awakening`（有生死、25+）→ `awakening_complete`（有种子）→ `mortal_market`（心关已开）。
4. 过滤 `eventEligible`（once/seen、年龄、学籍、境界、flags）。
5. **学籍白名单**：蒙学只出 `MENGXUE_EVENT_IDS`，府学只出 `FUXUE_EVENT_IDS`（避免被江湖事耽误大考）。
6. 权重随机，且避免连续两幕同一事件。

### 6.3 现有 40 个事件（按年龄）

- 7–11 蒙学：`first_day`、`rain_roof`、`stone_match`、`herb_garden`、`graduation_trial`
- 11–15 府学：`craft_path`(必做)、`first_qi`、`route_debate`、`exam_prep`、`mentor_choice`
- 15+ 太学：`tai_library`、`life_question`、`state_debate`、`master_accept`
- 通用：`market_day`、`street_work`、`family_letter`、`fox_rain`、`friend_debt`、`bandit`、`plague`、`duel_insult`、`secret_realm`、`save_city`、`border_war`、`sect_invite`、`dao_insight`、`old_friend`、`legacy`、`sunset`
- 心性链：`life_chain`、`great_awakening`、`awakening_complete`、`heart_demon`、`mortal_market`、`mortal_walk`、`sick_child`
- 兜底：`quiet_cultivation`、`travel`、`forge_lesson`

### 6.4 结局（`buildEnding`，行 2811）

优先级：战死 → 走火入魔 → 归隐 → 四道同辉 → 单道大圆满 → 世界认可（大曜柱石）→ 开山（听雨庐主）→ 最高境界「有缺」。

## 7. 非境界玩法

### 7.1 委托（`generateTasks` / `takeTask`，行 2201 / 2420）

- 每次抽 3 条，按学籍/境界/百艺/钱财过滤；有垫付、风险、失败结果。
- 无学籍且有百艺时，**优先**生成「入 X 铺做工」。
- 接委托消耗 1–2 年；跨过 15 岁会错过太学大考（前端有红字警告 `schoolWarning`）。

### 7.2 修行（`trainStudy` / `trainCraft` / `workShop`，行 2540 / 2560 / 2601）

- 精进学业：+3 课业、+1 悟性，1 年。
- 修炼百艺：按 `craftChance = 18 + 天资*0.55 + 属性*0.15 - 等级*7` 判定；上限由 `craftCap`（天资分档）决定。
- 入铺做工：按百艺等级给钱（`60 + level*35`），仅非在校。

### 7.3 坊市 / 百艺 / 装备

- `publicMarket` 列出 12 件物品；购买只校验钱（境界只影响能否**使用**，不影响购买）。
- 兵器/法器/灵器统一为 `type:'weapon'` + `tier: mortal|artifact|spirit`，共用一个装备位；`weaponUsable()` 按 `requirement` 判能否使用。
- 阵盘 `trapping_disk` 属阵法，战斗中「战前布阵」一次性消耗。
- 货币铜为本位：1 金 = 100 银 = 10000 铜（`formatMoney` 双端各一份）。

## 9. 前端约定

1. **无弹窗**：事件、结果、瓶颈、斗法、结局全在 `#storyPanel` 内渲染；只有抽屉（`#drawerRoot`）与 toast。
2. 抽屉种类：`bag / arts / journal / craft / tasks / train / market / help / hidden / abandon`，由 `data-drawer` 触发，`openDrawer(kind)` 分派到 `renderXxxDrawer()`。
3. `ui.run` 是服务端 `publicState()` 的镜像；所有写操作走 `post()`，成功后 `setRun(data.state)` 重绘。
4. `run.mandatory` 为真时，事件下方不出现「接委托 / 修行 / 坊市」的替代入口，后端也会拒绝。
5. 「观己」按钮：未登录 → 提示登录；非 sysadmin → 提示无权限；sysadmin → 拉 `/hidden` 渲染。
6. 资源版本用 `?v=N` 查询串破缓存，改动 `app.css` / `game.js` 后**必须**同步提升四个 HTML 里的版本号。
