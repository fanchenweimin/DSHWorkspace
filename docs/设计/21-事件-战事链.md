# 设计 · 21 战事链与贡献结算

> 系统：**2x 事件系统 · 战事模块**
> 需求侧：`需求/21-事件-战事与国战.md` 全篇
> 依赖：`20`（事件流水线）、`04`（DSL）、`03`（状态路径）、`30`（战斗结算）
> **这一份只做两件事**：① 把"固定年份的战事"变成**日历数据 + 事件链**；② 把"贡献"变成**一条状态路径 + 一张兑换表**。

> **实现状态（r29 核对）**
> - ✅ **日历驱动已接**：`src/model/systems/calendar.js` 三件事——`phaseFor(year)` 推档、`sync(state)` 跨年落 `war.phase` 并写纪事、`due(state)` 找出"这一年到点且没打过"的那一条。`hand.hand()` 先问日历，再掷池子；日历事件**不参与权重**。
> - ✅ **参数以日历为准**：`calendar.params` 合并进 `event.args`，所以三座城共用一个模板、只有守备与月数不同。
> - ✅ **城破成链**：城战模板里"守城/出城"失败与"弃城"都会写 `flag.city_lost.<城>`；下一条的 `ifFlag` 才放行（北关破了才轮王北，王北破了才轮到长明，三城尽失才国战）。
> - ⬜ **贡献兑换**（战功换席位/配额）只做到 `merit.war` 一个计数口子，兑换表还没接。
> - ⬜ 城破对人口 / 灵脉 / 席位的影响没有（城池系统未接）。
> - ⬜ 跨年战事（`span: true`、月数 > 剩余月）现在会**错过**，还没走 `pending` 顺延。

---

## 1. 三条原则

```text
① 战事不掷骰        → 日历（data/calendar.json）驱动，不进权重池
② 战事不改公式      → 战斗结算仍走 rules/battle.js，战事只提供"容器"
③ 贡献不改修为      → merit 只能换身份/席位/配额，不许换 bar 与 p
```

**第 ③ 条是硬约束**（I21）：一旦允许"贡献换成功率"，三十年战功可以直接跳过朝元那道墙——`需求/11` 的"丹药不能让墙消失"就白写了。

## 2. 日历：战事的时间源

```json
// data/calendar.json
{
  "tbl.calendar": [
    { "atYear": 312, "event": "evt.war.warning.north",  "params": { "front": "north" } },
    { "atYear": 313, "event": "evt.war.city.beiguan",   "params": { "city": "beiguan", "order": 1 } },
    { "atYear": 313, "event": "evt.war.city.wangbei",   "ifFlag": "flag.city_lost.beiguan" },
    { "atYear": 313, "event": "evt.war.city.changming", "ifFlag": "flag.city_lost.wangbei" }
  ]
}
```

| 字段 | 语义 | 注意 |
| --- | --- | --- |
| `atYear` | 绝对年份（大曜历） | **不是相对年龄**；读档、重开都要能对上 |
| `event` | 要注入的事件 id | 必须是已存在的 `evt.*` |
| `params` | 传给事件的参数（城、方向、序） | 事件里用 `$arg.*` 读 |
| `ifFlag` | 条件注入 | 城没丢就不注入，**这是"链"的唯一实现方式** |

**为什么用日历而不是 `chain.delayMonths`**：战事的年份是**世界事实**（"313 年北关打起来了"），不是"某个玩家触发后才开始算"的私事。两个角色在同一局里应该看到同一个 313 年。

**加载期校验**：`atYear` 必须单调不减；同一个 `(atYear, event)` 不许重复；`event` 不存在直接报错。

## 4. 战事期的池子改写（`war.phase`）

```js
// state.war = { phase: 'peace' | 'warning' | 'city' | 'nation', since: 313, front: 'north' }
const WAR_MUL = { peace: 1, warning: 1.5, city: 3, nation: 6 };

function effWeight(s, e) {
  const bias = e.luckBias ? (s.luck - 50) * 0.002 : 0;          // 气运只管机缘/灾祸
  const war  = e.nature === 'war' ? WAR_MUL[s.war.phase] : 1;   // 战事期放大
  return clamp((e.weight + bias) * war, 0.1, 60);
}
```

**只改权重不够，必须同时抬优先级**：

| 时期 | 战事事件 `priority` | 理由 |
| --- | --- | --- |
| `peace` | 3–4 | 剿匪不该压过瓶颈 |
| `warning` | 3 | 预警给时间，不抢槽 |
| `city` | **1** | 城在烧，别的事都排后面 |
| `nation` | **1** | 国战期，日常事件基本不该出现 |

**优先级是"顺序"、权重是"份额"**（`20` §7）：只放大权重，战事会被高优先级的主线挤掉；只抬优先级，同一批里战事只有一条会年年上桌。两件事一起做，才是"战事占 60%"。

`war.phase` 的写入**只发生在三处**：日历注入（进入 `warning`/`city`）、城破宏（`city → city`、三城尽失 → `nation`）、国战结局宏（`nation → peace`）。**不许事件随手改**（否则会出现"国战开着，坊市又开了"）。

## 5. 城破：一次结算，改四个系统

```js
// macro: war.cityFall
function cityFall(S, city) {
  S.flag[`city_lost.${city}`] = true;               // 事件链的依据（§2）
  const c = S.world.city[city];
  c.population = Math.round(c.population * 0.55);    // 人口 −45%
  c.spiritMass.base = Math.round(c.spiritMass.base * 0.80);  // 灵脉 −20%
  c.seats.total = Math.max(1, c.seats.total - 2);    // 席位减 2
  S.world.war.front = city;
  if (allNorthLost(S)) S.world.war.phase = 'nation';
  bus.emit('cityFall', { city });                    // 表现层刷地图
}
```

| 被改的 | 为什么是它 | 下游 |
| --- | --- | --- |
| `flag.city_lost.*` | 唯一的"事实记录" | 日历注入（§2）、事件 `when` |
| `population` | 战乱死人 + 逃难 | 城池层人口回归（`20` §10.4） |
| `spiritMass.base` | 灵脉是地块，不是人口 | 养灵者的灵量份额直接缩水 |
| `seats.total` | 空席消失，竞争变烈 | 灵量分配（零和） |

**这是"城破"最狠的地方**：它不扣你的修为，它扣你**修炼的输入**。养灵者会立刻感到疼（份额少了），锻体/炼气者会在几年后感到疼（买不到药、请不到人）。

## 6. 贡献：一条路径 + 一张表

### 6.1 路径

| 路径 | 语义 | 上限 |
| --- | --- | --- |
| `merit.war` | 战功 | 无 |
| `merit.craft` | 百艺交付 | 无 |
| `merit.office` | 供职考绩 | 无 |
| `merit.total` | **派生**：三者加权和（战 1.0 / 艺 0.8 / 职 0.6） | 无 |

```js
// rules/merit.js
function meritTotal(S) {
  return S.merit.war * 1.0 + S.merit.craft * 0.8 + S.merit.office * 0.6;
}
// 每年年初，衰减 10%（不进修饰器，直接写基础值）
function decayMerit(S) {
  for (const k of ['war', 'craft', 'office']) S.merit[k] = Math.round(S.merit[k] * 0.9);
}
```

**衰减放在 `rules/` 而不是 `data/`**：它是"贡献会过期"这条世界规则的实现，不是可调内容。允许策划改衰减率，等于允许把"功勋"变成"存款"。

### 6.2 兑换表（这是数据）

```json
// data/merit.json
{
  "tbl.merit.exchange": [
    { "id": "ex.rank",     "cost": 200, "limit": "oncePerRank", "do": [ { "call": { "macro": "identity.promote" } } ] },
    { "id": "ex.seat",     "cost": 0,   "limit": "annualRank", "do": [ { "call": { "macro": "seat.allocate" } } ] },
    { "id": "ex.pill",     "cost": 40,  "limit": "perYear3",   "do": [ { "grant": { "item": "guben", "n": 1 } } ] },
    { "id": "ex.exempt",   "cost": 80,  "limit": "perYear1",   "do": [ { "flag": { "id": "flag.exempt_this_year", "value": true } } ] },
    { "id": "ex.lifePill", "cost": 500, "limit": "lifeTime3",  "do": [ { "call": { "macro": "shop.unlock", "args": { "item": "yanshou" } } } ] }
  ]
}
```

| 字段 | 语义 |
| --- | --- |
| `cost` | 消耗 `merit.total`（0 = 按排名分配，见 `seat.allocate`） |
| `limit` | `oncePerRank` / `annualRank` / `perYear3` / `perYear1` / `lifeTime3` |
| `do` | 一律走宏，**不许直接 `add` 修为或 `p`** |

**席位是"排名"不是"购买"**：`ex.seat` 的 `cost: 0`，由 `seat.allocate` 在每年城池层按 `merit.total` 排序分配（`20` §10.4 ⑤）。这样"贡献高"直接等于"灵量份额高"，中间不需要货币。

### 6.3 义务：让"只进不出"付出代价

身份不是白拿的，每个身份带一条**年度义务**，实现方式是**强制事件**（不新增机制）：

```json
// data/identity.json
{ "id": "id.army.captain", "name": "边军校尉",
  "require": { "realm": { "dao": "qi", "gte": 2 }, "merit": 100 },
  "duty": { "perYear": 3, "months": 2, "event": "evt.duty.garrison",
            "penalty": [ { "add": ["merit.office", -15] }, { "call": { "macro": "identity.demote" } } ] } }
```

| 字段 | 语义 |
| --- | --- |
| `perYear` | 每年最多几次 |
| `months` | 每次义务占几个月（军令 2–6 月） |
| `event` | 由哪个强制事件承载 |
| `penalty` | 没履行时结算（降贡献 + 降身份） |

**义务是"修炼的税"**：身份越高，义务越重（校尉每年 2 月戍守，将军 4 月）。玩家想要俸禄与灵量，就得拿出月份——**这就是"不能只进不出"的机制版本**。

## 7. 与 `20` 的接缝（三处，别写重）

| 接缝 | 谁负责 | 接口 |
| --- | --- | --- |
| 日历注入 → 事件池 | `20` §9 年初 ⑦ | `injectCalendar(s)` 把当年事件直接塞进 `s.turn.candidates`，**标 `fromCalendar: true`**（不参与权重，直接上桌） |
| 强制事件封常驻 | `20` §9 | 已有 `pickMain(s)?.forced`，战事复用，不改 |
| 城破改城池 | `20` §10.4 | 城池层只读 `world.city`，城破写在 `systems.war`，顺序：城池层 → 战事层 → 事件掷骰 |

**顺序很重要**：城池层要先算完（人口回归、灵脉重算），战事层再改（打完了才死人），最后才掷事件（今年的世界已经变了）。

## 8. 断言

| 场景 | 期望 |
| --- | --- |
| 日历 `atYear` 乱序 | 加载失败 |
| 日历引用不存在的事件 / 城 | 加载失败 |
| 战事事件进了权重池 | 断言失败（`fromCalendar` 的必须直接上桌） |
| `war.phase = 'nation'` 时坊市可用 | 断言失败（`zone: battle` 强制覆盖） |
| 城破三次（三城尽失） | `phase` 变 `nation`；不允许第四次城战 |
| `merit.total` 被事件直接加 | 加载失败（只能加三个分项） |
| 兑换 `cost` 换修为 / `p` | 加载失败（I21） |
| 义务未履行 | 年初结算 penalty，且 `merit.office` 不会变成负数（钳 0） |
| 国战结束 | `phase → peace`，`since` 清空，日历不再注入同一条 |
| 读档在国战中途 | `war.phase` / `since` / `flag.city_lost.*` 必须一起恢复 |
