## 1. 一条原则

```text
事件 = 触发器（when） + 权重（weight/priority/forced） + 时长（months/span） + 选项（choices） + 效果（do）
```

**没有一个字段是函数。** 旧版 `require: (s) => …`、`effects: (s, ok) => …` 全部改成声明式，理由见 `04` §1：策划要能自己加事件。

## 4. 模板：22 个瓶颈不写 22 份

**这是"逻辑聚合"在事件层的落地。** 22 个境界瓶颈结构完全一样（条件 + 判定 + 成败分支），差别只有 `dao` / `tier` / 文案。所以：

```json
// data/templates.json
{
  "tpl.break.prob": {
    "params": ["dao", "tier", "title"],
    "nature": "bottleneck", "priority": 2, "forced": true, "months": 6, "span": true,
    "when": [
      { "eq": ["path.$arg.dao.level", "$arg.tierMinus1"] },
      { "gte": ["path.$arg.dao.bar", "$prof.$arg.dao.$arg.tier"] }
    ],
    "judge": { "kind": "break", "dao": "$arg.dao", "tier": "$arg.tier" },
    "choices": [
      { "id": "try", "label": "冲关", "cost": "$arg.months",
        "do": [ { "call": { "macro": "break.attempt", "args": { "dao": "$arg.dao", "tier": "$arg.tier" } } } ] },
      { "id": "wait", "label": "再等一年", "cost": 0, "do": [] }
    ]
  }
}
```

```json
// data/events/break_qi.json —— 一个境界一行
{ "id": "evt.break.potai", "template": "tpl.break.prob", "args": { "dao": "qi", "tier": 2, "title": "破胎" } }
{ "id": "evt.break.yufan", "template": "tpl.break.prob", "args": { "dao": "qi", "tier": 3, "title": "驭凡" } }
```

**三层复用**（与 `04` §4.5 对应）：

| 层 | 例子 | 谁改 |
| --- | --- | --- |
| 算子 | `add` / `judge` / `mod` | 程序（一次） |
| 宏 | `macro.break.attempt`（判定 + 成败分支 + 清条） | 程序/主策 |
| 模板 | `tpl.break.prob`（22 个瓶颈共用的骨架） | 主策 |
| 实例 | `evt.break.potai`（一行参数 + 文案） | 策划 |

## 6. 四步入池（不掷骰）

**⓪ 日历注入先于一切**：

```js
function injectCalendar(s) {
  const hits = CALENDAR.filter(k => k.atYear === s.clock.year
                               && (!k.ifFlag || s.flag[k.ifFlag]));
  for (const k of hits.sort((a, b) => (a.order ?? 0) - (b.order ?? 0))) {
    const ev = EVENTS[k.event];
    if (!ev) throw new Error(`日历引用了不存在的事件 ${k.event}`);
    s.turn.candidates.unshift({ ...ev, args: k.params, fromCalendar: true });
  }
}
```

日历事件**不过 ①–④**（时间窗、条件、额度都不查）——因为"世界记着这件事"。但仍要过 `handled`：打完一次就不再上桌。

```js
function inPool(s, e) {
  if (!inWindow(s, e.window))       return false;   // ① 时间窗
  if (!evalCond(s, e.when))         return false;   // ② 触发条件（见 04 §3）
  if (!quotaOk(s, e))               return false;   // ③ 资格额度
  return true;                                      // ④ 入池：不掷骰
}
```

**`weight` 不在这步消费。** 旧实现 `if (roll() < rate * 0.1)` 是错的——它把权重当年闸，于是低档事件可能连着几年抽不到，而"10 档"被误读成"必出"。

## 7. 上桌：优先级批次 + 权重归一化

```js
function pickMain(s) {
  const cands = EVENTS.filter(e => inPool(s, e) && !s.turn.handled.includes(e.id));
  // 日历事件已经在 s.turn.candidates 里，这里只要保证它们排在前面
  if (!cands.length) return null;

  const minP  = Math.min(...cands.map(e => e.priority));   // ⑤ 取最小批
  const batch = cands.filter(e => e.priority === minP);

  const forced = batch.filter(e => e.forced);
  if (forced.length) return weighted(s, forced);           // 强制占第 1 槽

  return weighted(s, batch);                               // 批内按权重抽
}

function weighted(s, batch) {                              // p_i = w_i / Σw
  const total = batch.reduce((a, e) => a + effWeight(s, e), 0);
  let r = Math.random() * total;
  for (const e of batch) { r -= effWeight(s, e); if (r <= 0) return e; }
  return batch[batch.length - 1];
}

function effWeight(s, e) {                                 // 气运只偏置机缘/灾祸
  const bias = e.luckBias ? (s.luck - 50) * 0.002 : 0;
  return clamp(e.weight + bias, 0.1, 10);
}
```

**四条硬规则**：

1. `priority` 是层级不是概率：小者先，**只在同批内**用 `weight` 破同分。
2. `forced` 压过批内一切，**不参与归一化**；多条强制时按 `weight` 抽一条，其余下个月。
3. **每处理完一条就重算批**（不是年初排完全年）：权重和随之变小，后面每条份额上升。
4. **有强制事件时，常驻模块整体不可用**（§9）。

### 7.1 权重 ≠ 概率

| 场景 | 权重和 | 单条命中率 |
| --- | --- | --- |
| 5 条：1/2/3/4/5 | 15 | 1→6.7%，5→33.3% |
| 3 条：3/5/8 | 16 | 3→18.8%，8→50.0% |
| 1 条：10 | 10 | **100%** |

**14 万次模拟（5 条权重 1–5，每条 3 月，一年做 4 件）**：

| 事件 | 第 1 个 | 第 2 个 | 第 3 个 | 第 4 个 | 一次没抽到 |
| --- | --- | --- | --- | --- | --- |
| 权重 1 | 6.5% | 8.4% | 11.8% | **19.2%** | 54.1% |
| 权重 3 | 20.6% | 21.4% | 24.0% | 22.0% | 12.0% |
| 权重 5 | 32.9% | 28.1% | 21.3% | 13.3% | 4.4% |

**读法**：低权重只是"晚"，不是"没有"。**要必出用 `forced`；要稀有用 `weight: 1` + `quota.cooldown`**。

## 8. 判定与选项

```json
{
  "judge": { "kind": "break", "dao": "qi", "tier": 4 },
  "choices": [
    { "id": "try",  "when": [], "cost": 12,
      "do": [ { "call": { "macro": "break.attempt", "args": { "dao": "qi", "tier": 4 } } } ] },
    { "id": "bribe", "when": [ { "has": ["item.jade", 1] } ], "cost": 1,
      "do": [ { "grant": { "item": "jade", "n": -1 } }, { "add": ["path.qi.fail", 0.01] } ] }
  ]
}
```

- `judge` 在**选项执行前**跑一次，结果放 `$last`，宏里用 `{"eq": ["$last.ok", true]}` 分支。
- `choices[].when` 决定**选项可不可见/可不可点**；不可点时用 `why` 给文案（`{"try": "修为未满"}`）。
- **任何置灰必须有 `why`**（原型 `turn-proto.html` 的四件套 `{name, cost, desc, why}`）。

## 9. 月循环（engine，规则不变）

```js
function tickYear(s) {
  // ── 年初（自动，顺序写死）────────────
  if (!step1_lifespan(s)) return endYear(s);
  step2_luck(s); step3_heart(s); step4_demon(s); step5_city(s);

  const pending = s.turn?.pending ?? null;
  s.turn = { monthsLeft: 12, candidates: [], handled: [],
             pending, breakthroughUsed: false, studyUsed: 0 };

  advancePending(s);                        // 跨年动作先扣月
  if (!s.turn.pending) {                     // 闭关/出征时不掷新事件
    injectCalendar(s);                       // ⓪ 日历（战事/主线节点）先塞进来
    step6_rollEvents(s);                     // 再跑四步入池
  }

  // ── 月内（玩家驱动）──────────────────
  while (s.turn.monthsLeft > 0 && s.alive) {
    const main = pickMain(s);
    if (main && main.forced) { resolve(s, main); continue; }   // 强制：常驻全灰

    const pick = waitPlayerChoice(s, { resident: residentAvailable(s), main: true });
    if (!pick) break;
    resolve(s, pick);
  }
  return endYear(s);
}

function residentAvailable(s) { return !pickMain(s)?.forced; }

function resolve(s, ev) {
  const cost = ev.months ?? 0;
  if (cost === 0) { applyEffects(s, ev.do); s.turn.handled.push(ev.id); return 'done'; }

  if (cost > s.turn.monthsLeft) {
    if (!ev.span) return 'blocked';
    s.turn.pending = { eventId: ev.id, remaining: cost - s.turn.monthsLeft, total: cost };
    s.turn.monthsLeft = 0;
    return 'spun';
  }
  s.turn.monthsLeft -= cost;
  applyEffects(s, ev.do);
  s.turn.handled.push(ev.id);
  if (ev.nature === 'bottleneck') s.turn.breakthroughUsed = true;
  return 'done';
}
```

**四条顺序约束**（与 r20 相同，不要动）：

1. 跨年动作先于玩家（`advancePending` 在月循环前）；
2. 跨年期间不掷新事件；
3. 强制判定用**实时** `pickMain`，不是年初快照；
4. **年末只清账，不推进 pending**（推进在次年年初），否则同段月被扣两次。

## 10. 事件链与额度（数据化）

```json
{ "id": "evt.mainline.sect_trial", "quota": { "once": true, "cooldown": 0 },
  "chain": { "key": "sect_trial", "step": 2 },
  "do": [ { "chain": { "event": "evt.mainline.sect_trial.3", "delayMonths": 24 } } ] }
```

| 字段 | 语义 | 注意 |
| --- | --- | --- |
| `quota.once` | 一生一次 | 记在 `flag` |
| `quota.cooldown` | 冷却月数 | 记 `lastFiredAt` |
| `quota.perYear` | 每年上限 | 记 `firedThisYear` |
| `chain.key/step` | 同一个故事线的第几步 | 用于文案排序与跳过 |

**`once` 与 `cooldown` 是两件不同的事**：`weight` 只决定"什么时候轮到"，`quota` 决定"还能不能再出现"。两者必须都写，否则低权重事件在月份充足时会年年上桌。

## 11. 加一个事件的工作流（策划视角）

```text
① 想清楚：什么时候遇到（window）→ 满足什么（when）→ 玩家能选什么（choices）→ 选完发生什么（do）
② 有现成模板（22 个瓶颈 / 主线 / 机缘）→ 只写 args
③ 没有模板 → 直接写完整 JSON，效果引用现成宏（break.attempt / money.gain / mod.apply）
④ 放进 data/events/<域>.json，跑 `npm run check:data`
⑤ 静态校验过 → 游戏里能刷到
```

**不需要碰代码。** 只有当你要的效果在 `ops.json` 里找不到时（例如"改变天气"），才需要注册一个新算子（`04` §10）。

## 12. 边界与断言

| 场景 | 期望 |
| --- | --- |
| 池子为空 | `pickMain` 返回 `null`，主要区空，常驻照常可用 |
| 同批有 `forced` | 必返回 `forced`（多条按 `weight` 抽一条，其余下月） |
| 有强制未处理 | `residentAvailable === false`，7 个常驻全灰，`why = '有强制事件待处理'` |
| 强制事件 `months > 12` | 必须 `span: true`，否则断言失败 |
| 常驻 `months > maxMonths` | 断言失败；UI 置灰 + `why` |
| 主要事件 36 月、本年剩 2 月 | `pending.remaining = 34`，次年先扣 12、再扣 12、第三年扣 10 后结算 |
| 跨年进行中 | 本年 `candidates` 为空，玩家只能等或放弃 |
| 同批 5 条权重 1/2/3/4/5 | 首条命中率 ≈ 1/15 |
| 瓶颈与主线同年 | 先瓶颈（优先级 2），主线明年 |
| 同年两次突破 | 断言失败 |
| `once` 已用 / `cooldown` 未到 | 不入池 |
| 求学已封顶 | `when` 为假，卡片**不出现**（不是置灰） |
| `when` 求值抛错 | 视为不入池 + 记日志，不许整局崩 |
| 日历事件与池内事件同日 | 日历事件先上第 1 槽（`fromCalendar` 不参与归一化） |
| 日历 `atYear` 已过（读档跳到 320 年） | 补注入该年之前的**全部**未处理日历事件（按 `order`），不许静默跳过 |
| 战事期（`war.phase != 'peace'`） | 坊市/委托/求学全部不可用；`act.combat` 出现 |
| `duty` 未履行 | 年初生成强制事件；年末仍未处理 → `penalty`（`21` §6.3） |
| 年末还剩月 | 清零，不结转 |
| 候选未处理 | **直接作废**，不结算、不补发 |

## 13. 与 r20 的差异

| 项 | r20 | r22 | 为什么 |
| --- | --- | --- | --- |
| `require` | `(s) => bool` 函数 | **`when` 条件数组**（`04`） | 用户要自己配事件 |
| `effects` | `(s, ok) => void` 函数 | **`do` 效果数组** | 同上 |
| 22 个瓶颈 | 22 份对象 | **1 个模板 + 22 行参数** | 逻辑聚合 |
| 常驻动作 | 代码对象 | **`data/actions.json`** | 同上 |
| 判定 | `judge: 'b'` 字符串 | **`{kind:'break',dao,tier}` 具名判定器** | 公式锁在 rules，配置只选 |
| 权重/优先级/强制/跨年 | 已定 | **不变** | r20 的四条硬规则是对的 |
| 月循环 | 已定 | **不变**（只把 `applyOutcome` 换成 `applyEffects`） | |
| 事件来源 | 只有池子 | **池子 + 日历**（`fromCalendar` 跳过权重） | 战事必须是世界事实（`21`） |
| 身份 | 只有收益 | **带 `duty` 年役** | 修炼不能只进不出 |

## 14. 实现（r26-4）：与上面伪代码的几处偏差

代码在 `src/model/systems/draw.js`（抽）与 `hand.js`（桌上摆什么）。§6/§7 的规则一条没改，
但为了让"按需渲染"的网页跑得通，有几处必须写死的东西，记在这里，免得下次有人照伪代码改回去。

### 14.1 主卡要记住，不能每刷一次重掷

§7 的 `pickMain(s)` 是月循环里的内联函数——一局只调一次。Web 这边是"一次请求渲染一次桌子"，
如果每次 `GET /api/hand` 都重掷，玩家会看见卡在两张之间来回跳。

```js
state.turn.mainId   // 抽中的 id；结算完 / 跨年才清空
```

- 还在池子里就照旧给它（不重掷）；
- 掉出池子（被 `quota` 挡住、条件不成立）就清空重抽；
- `commit()` 与 `rollYear()` 都会清空——即"每处理完一条就重算批"。

### 14.2 `ttl` 的计时起点是**第一次入池**，不是事件被创建

```js
state.seen[id] = absMonth   // 第一次通过 ①②③ 的那一月
过期条件：absMonth - seen > ttl * 12
```

城战写着 `ttl: 3`：三年之内不打，这座城就不问了。`seen` 必须存档，否则读档能续命。

### 14.3 绝对月序号用 `年*12 + 本年已耗`，不用 `clock.month`

`clock.month` 现在没有任何地方推进（月份靠 `monthsUsed` 记），拿它算冷却会永远停在 1 月。
`draw.absMonth()` 与 `effects.absMonth()` 是同一个口径。

### 14.4 多了一条 `canWait`（死锁兜底）

`§9` 的语义是"主卡付不起月份就 `blocked`，这一年结束"。但页面没有"结束这一年"的按钮，
强制事件要 5 个月、只剩 3 个月时，常驻又被 I15 封住 —— 玩家会彻底卡死。

所以 `table()` 多返回一个 `canWait`：**这一年还有月，却没有一件做得成的事**。
前端这时给一张"把这一年过完"，走 `POST /api/act {kind:'wait'}`，等价于 `endYear`。
它不是新规则，只是把 §9 里那句隐式的 `break` 变成玩家能点的东西。

### 14.5 22 品的数据形状

22 个瓶颈 = 7 条 `tpl.break.prob` + 15 条 `tpl.break.event`，每条只写 `args: {dao, tier}` 与文案。
品 5 / 品 6 的"硬条件"目前只能用现有字段近似：

| 品 | 文档条件 | 现在用什么 |
| --- | --- | --- |
| 锻体 5 金身 | 朝元圆满 + 一次公开战功 | `merit.war ≥ 100`（战功的代用品） |
| 锻体 6 临虚 | 金身圆满 + 无法力死战不死 | `merit.war ≥ 200`（同上，战斗系统未接） |
| 养灵 5 浑然 | 神游圆满 + 治下生灵认可 | `reputation.eff ≥ 60` |
| 养灵 6 回春 | 浑然圆满 + 还灵不死 | `reputation.eff ≥ 80` |
| 修心 1–4 | 心性 ≥ 90 + 道心门槛 | `attr.heart.eff ≥ 90` + `cond.break_ready` |

这四行是**临时口径**，等战斗 / 城池系统接上要换掉（记在 `PROGRESS.md` r26-12）。
