# 设计 · 03 状态路径与修饰器（公共因素 ①）

> 系统：**0x 全局 · 数值管线**
> 需求侧：`需求/01`（属性与气运）、`需求/14` §1.2（药与宝地）、`需求/11`（突破资源）
> 这一份解决一个问题：**同一个数值被五个系统读写，怎么保证改一处、处处一致。**
> 结论：状态是一棵**可寻址的树**，所有读走 `resolve()`，所有写走 `write()`，所有"临时/永久加成"都是**同一种对象**——修饰器。

---

## 1. 为什么需要这一层

现在散在代码里的写法是这样的：

```js
// 修炼算出月修为
const rate = base * 0.2 * (hasPill ? 1.1 : 1);
// 突破算出成功率
const p = attr.insight * 0.003 + (hasPill ? 0.05 : 0);
// 面板显示资质
const shown = attr.aptitude + washBonus + bathBonus;
```

三处各自记住"哪些加成算进来"，于是：加一种新药要改八处；药到期了某处忘了减；面板 62、判定按 59 算。

**修法**：加成不是代码分支，而是**数据**。属性本身不变，只有 `resolve()` 的结果变。

---

## 2. 状态树与路径

路径是 `域.对象.字段`，点分，全部小写。**配置里提到的每一个数值，都必须有路径。**

| 域 | 路径示例 | 说明 |
| --- | --- | --- |
| 钱 | `money.gold` / `money.silver` / `money.copper` | 铜为最小单位，读写走 `money` 系统 |
| 属性 | `attr.aptitude` / `attr.insight` / `attr.heart` / `attr.nature` | **基础值**，只有洗髓这类永久改造才写它 |
| 修为 | `path.body.level` / `path.qi.bar` / `path.spirit.bar` | 四道各自的层级与条 |
| 判定 | `path.qi.fail` / `path.qi.attempts` | 失败累积与次数 |
| 身份 | `identity.base` / `identity.seat` / `education.stage` | |
| 世界 | `city.population` / `city.seats.used` / `spiritMass.own` | |
| 气运 | `luck` / `fate` | `luck` **不吃修饰器**（见 I5） |
| 时钟 | `clock.year` / `clock.age` / `clock.month` | 只读 |
| 标记 | `flag.seen_lixiang` / `flag.studied_qi_4` | 布尔或计数 |
| 物品 | `item.peiyuan` / `item.xisui` | 数量 |
| 关系 | `npc.<id>.favor` | |

**派生路径**：所有"显示/判定用的值"都是 `基础路径 + .eff`。

```js
resolve('attr.aptitude.eff')   // 55 + 洗髓 3 + 药浴 3 = 61
resolve('attr.aptitude')       // 55（基础值，几乎没人该读它）
```

> **规则**：除"洗髓/药浴/成长"这三类**永久改造**外，任何代码都禁止直接读 `attr.*`，一律读 `.eff`。审查看 `grep -n "attr\.\w\+[^.]" `，出现即违规。

## 3. 修饰器：永久与临时是同一种东西

用户这轮点明的区分——**洗髓药浴是永久的，悟道丹、宝地是临时的**——在数据上不是两种系统，而是**同一个对象的 `duration` 不同**。

```js
{
  id: 'mod_7',                       // 运行期唯一
  target: 'attr.aptitude.eff',       // 路径（必须带 .eff）
  op: 'add',                         // add | mul | setMin | setMax
  value: 3,
  duration: { kind: 'permanent' },   // 见 §3.1
  source: 'item.xisui',              // 来源 id，同源互斥用
  stack: 'unique',                   // unique | stack | max
  tags: ['永久', '根骨']              // 只给表现层与筛选用，不参与计算
}
```

### 3.1 时长五种

| `duration.kind` | 含义 | 例子 | 过期处理 |
| --- | --- | --- | --- |
| `permanent` | 永不掉，写进「永久账」 | **洗髓 +3 资质**、**药浴 +3 资质** | 不处理 |
| `years` | 按年，`value: n` | 悟道丹 +5 悟性（1 年）、宝地 +3 资质（1 年） | 每年年初 `expire()` |
| `months` | 按月，`value: n` | 固本丹（当年有效）、临时阵法 | 每月 `expire()` |
| `until` | 到某个条件为止 | `until: {flag:'wounded'}` | 条件成立即摘 |
| `battle` | 战斗结束即清 | 战前服丹 | 战斗结算末尾整批清 |

**永久不是"很长的时间"，是"不进过期队列"**。洗髓的 +3 永远在 `state.mods` 里躺着，存档时一起存。

### 3.2 叠加三条硬规则

1. **同源唯一**（`stack: 'unique'`）：`source` 相同的修饰器，新的替换旧的，不叠加。药浴第 2 年不会变成 +6 以外的怪值——药浴每年 +1 是**三条不同的 source**（`item.yaoyu.1/2/3`）或一条 `permanent` 的累加写法。
2. **异源叠加**（`stack: 'stack'`）：洗髓 +3 与药浴 +3 相加 = +6。
3. **取大**（`stack: 'max'`）：同类丹药不叠，只取最高（防"连嗑十颗固本丹"）。

> **修为条不吃修饰器**（I2：四道互不相通）。`path.*.bar` 只能被 `add`（修炼产出）与 `set 0`（破境清零）改写，任何 `mul` 到修为条上的配置在加载期即报错。

## 4. 结算管线（唯一入口）

```js
function resolve(state, path) {          // path 形如 'attr.aptitude.eff'
  const base = getBase(state, path);     // 去掉 .eff 的存储值
  const mods = state.mods.filter(m => m.target === path);
  let v = base;
  for (const m of mods) if (m.op === 'add') v += m.value;          // ① 加法层
  for (const m of mods) if (m.op === 'mul') v *= m.value;          // ② 乘法层（value 是倍数）
  for (const m of mods) if (m.op === 'setMax') v = Math.max(v, m.value);
  for (const m of mods) if (m.op === 'setMin') v = Math.min(v, m.value);
  return clamp(round(v), LIMIT[path]?.[0] ?? -Infinity, LIMIT[path]?.[1] ?? Infinity);
}
```

> **`mul` 的 `value` 是倍数，不是增量**：培元丹写 `1.10`（×1.10），不是 `0.10`。`items.json` 与 `设计/04` §4.1 的例子都按倍数写，管线必须同一口径——否则同一份配置在两处差出 10 倍。

**四层顺序固定**：加 → 乘 → 取大 → 取小 → 钳制 → 取整。这样**配置顺序不影响结果**（否则"先加后乘"和"先乘后加"会差出数字，配置一改就翻车）。

| 层 | 典型 | 为什么在这层 |
| --- | --- | --- |
| `add` | 洗髓 +3、药浴 +3、宝地 +3 | 固定点数，直觉可加 |
| `mul` | 培元丹 月修为 ×1.10、灵量 ×份额 | 比例增益，连乘可解释 |
| `setMin/Max` | "不低于 10"、"不超过 95%" | 兜底钳，放最后 |
| `clamp` | 成功率 ≤ 0.95、属性 ≤ 78 | 系统级硬边界，写在 `LIMIT` |

### 4.1 三处必须走管线的结算

| 结算 | 路径 | 备注 |
| --- | --- | --- |
| 月修为 | `rate.realm.month.eff` | = 基数 × 0.20 × 培元 × 灵量 |
| 突破成功基数 `b` | `break.prob.b.eff` | 见 `11` §4 |
| 面板显示 | 全部 `.eff` | UI 只读 `resolve()`，不自己算 |

**气运不在管线里**（I5）：`luck` 只在**掷骰点**以加法注入（`p + luckAdj`、权重偏置、进位），绝不写进 `mul`。

## 5. 写入与缓存失效

```js
function write(state, path, value, why) {
  setBase(state, path, value);
  state.rev++;                       // 版本号 +1
  bus.emit('changed', { path, value, why });
}
```

- **`rev` 是缓存钥匙**：修炼基数缓存 keyed by `rev`，任何写入都会让它失效，杜绝"面板变了判定没变"。
- **`bus` 是表现层与成就的唯一入口**：UI 不轮询 state，只订阅 `changed`。
- **修饰器增删也走 `write`**（`state.mods` 增删后 `rev++`）。

## 6. 与资源的对接（用户这轮的两类资源）

| 资源 | 类型 | 落地 | 效果 |
| --- | --- | --- | --- |
| 洗髓丹 | **永久** | `{op:'add', value:3, duration:{kind:'permanent'}, source:'item.xisui'}` | 资质永久 +3，进永久账 |
| 药浴 | **永久** | `permanent`，每年一条（`source: 'item.yaoyu.<year>'`） | 3 年 +3，不可逆 |
| 悟道丹 | **临时** | `{op:'add', value:5, duration:{kind:'years', value:1}}` | 悟性 +5，一年后自动掉 |
| 宝地历练 | **临时** | `{op:'add', value:3, duration:{kind:'years', value:1}}` | 资质 +3，离开即掉 |
| 固本丹 | **临时** | `target: 'break.prob.bonus.eff'`，`months: 12` | 破境 `p` +0.05，当年 |
| 喂招 | **临时** | 同上，`months: 12` | 破境 `p` +0.08，当年 |
| 培元丹 | **消耗** | 不落修饰器，走 `item.peiyuan--` + `rate.realm.month` 的 `mul` | 月修为 ×1.10 |

> **永久与临时的分界只看一件事：会不会自己掉。** 洗髓不会掉，所以它改的是"这个人的底子"；宝地会掉，所以它只是这一年更好过。两者在 `resolve()` 里没有区别——这正是这一层存在的意义。

## 7. 与人口校准的关系

`设计/15` 的蒙特卡洛就是这套管线的**离线版**：`sup`（资源覆盖）决定抽不抽得到永久/临时资源，属性 `.eff` 决定 `b` 与 `q`。
校准里"永久 +3 资质"与"临时 +3 资质"的差别只在**是否跨年**——一年内两者对 `p` 的作用完全相同，这正是 §3.1 的语义。

## 8. 断言（写代码前先写这五条）

| 场景 | 期望 |
| --- | --- |
| 洗髓 +3 后再服一次 | `stack:'max'` 或 `unique` → 仍 +3，不会 +6 |
| 洗髓 +3 与药浴 +3 | +6（异源叠加） |
| 悟道丹到期 | 次年年初 `attr.insight.eff` 回落到原值，且 `rev++` |
| 对 `path.qi.bar` 配 `mul` | **加载期报错**（违反 I2） |
| 同一个值先加 3 再乘 1.1，与先乘后加 | 结果必须相同（分层固定） |
