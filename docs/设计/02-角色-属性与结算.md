## 1. 属性生成

```js
S = U(110, 130)                    // 出生"和"
r = U(0.40, 0.60)                  // 偏科系数
aptitude = round(S * r)            // 资质
insight  = round(S * (1 - r))      // 悟性
heart    = round(U(40, 90))        // 心性
luck     = round(clamp(U(30, 90), 20, 95))   // 气运
```

- 结果范围：资质/悟性 **44–78**，均值 60、sd 7.5。
- 命格 `fate` / 天赋在**这之后**加，且可以突破 78（上限 100）。
- **教育不进入这一步**（I8）。

**为什么 `r ∈ [0.40, 0.60]`**：它保证"和 110–130 的人，不可能双 80"——双 80 需要 S ≥ 160。这条是"双 80 是全游戏最窄的门"的算术来源。

## 2. 修炼基数：属性、功法、境界的加权和

**三道同构，一套权重**：

```text
基数 = 0.70 × 属性 + 0.20 × 功法值 + 0.10 × 境界值

属性  ：锻体 = 资质；炼气 = 悟性；养灵 = (资质 + 悟性) / 2
功法值：由功法/势力品阶查表（见 §2.1）
境界值：30 + 10 × 品        （品1 = 40 … 品6 = 90）
```

**修心没有基数**——道心只由心关事件推进（见 §5）。

### 2.1 功法值表

| 品阶 | 功法值 | 谁有 |
| --- | --- | --- |
| 黄下 | **30** | 无学籍（r17 起不再出现） |
| 黄中 | **38** | 蒙学 |
| 黄上 | **46** | 府学 |
| 玄 | **54** | 太学 |
| 地 | **58** | 大宗门 / 世家嫡传 |
| 天 | **60** | 圣地 / 道统 |

**养灵没有"功法"，它的功法位是势力档次**：小宗 38 / 大宗 46 / 圣地 54。

### 2.2 月修为

```text
锻体 / 炼气：月修为 = 基数 × 0.20 × 乘区
养灵：      月修为 = 基数 × 0.20 × 灵量系数      （灵量系数见 §4）
修心：      无月修为，走心关（§5）
```

**系数 0.20 保持不变，改的是修为量（r21）**：

| 品 | 旧修为量 | **新修为量** | 资质 55 / 黄中 38 / 月 10.0 |
| --- | --- | --- | --- |
| 体魄 | 470 | **120** | 12 月 |
| 脏腑 | 720 | **260** | 26 月 |
| 调息 | 1,050 | **1,600** | 160 月 |
| 朝元 | 1,500 | **2,500** | 250 月 |

**为什么前两品砍到 1/4、品 3 反而加 50%**：因为需求要"10 岁蒙学毕业时锻体脏腑过半"与"30 岁脱离凡人保持 90%"同时成立，只有一个解——**前段快、后段慢、中间靠瓶颈拖**：
- 前两品合计 380 点 → 资质 55 的孩子 **3.1 年**走完（10.1 岁到脏腑，实测锻体组 65.7%）；
- 品 3 一口气 1,600 点 → 12–15 年，修满时约 22 岁；
- 修满之后还要磨调息那道墙 **3–4 年**（运气差 8–10 年）——**这一段就是"修为满了去学术法百艺"的窗口**。

> **旧锚点 470 / 45.5 月的算术作废。** 它让品 1 就要 4.2 年，7 岁入学的孩子到 11 岁才到体魄，10 岁前到脏腑的比例是 **0%**——与"蒙学毕业一半以上到脏腑"直接冲突。**修为条不是越长越有味道；长出来的那部分时间应该给瓶颈，不是给打坐。**

### 2.3 四道的年修为对照（属性 60 / 黄上 / 品 1）

| 道 | 基数 | 月修为 | 年修为 | 乘区 |
| --- | --- | --- | --- | --- |

**养灵时钟锚点**（双 90 / 圣地 / 城主级灵量 100 万）：

| 品 | 修为量 | 年修为 | 累计年 |
| --- | --- | --- | --- |
| 开视 | 5,400 | 373 | **14.5** |
| 启灵 | 13,500 | 373 | 50.6 |
| 真域 | 21,600 | 373 | **108.5** |

## 4. 灵量：养灵唯一的乘区（r18 改基数制）

```text
灵量基数：凡人 1 / 修士 10 / 其他生灵 1（开智的按修士计）
城池灵脉 = Σ 治下所有生灵的灵量基数
个人灵量 = 分到的那一份           （零和）
灵量系数 = clamp(2 × 个人灵量 / 城池灵脉, 0.2, 6)
月修为   = 基数 × 0.20 × 灵量系数
```

**为什么用"份额 ×2"而不是"绝对值 ÷50 万"**：份额 ×2 就是系数，所以"分 10% 慢 10%"永远成立，不管这座城是 10 万人还是 300 万人。绝对值的写法会被"城的规模"污染——两座人口差十倍的城，同样的份额却给出不同的系数。

| 情形 | 份额 | 灵量系数 | 双 90 养灵年修为 |
| --- | --- | --- | --- |
| 城主独占（100 万人口的城 ≈ 910 万灵量） | 100% | **2.0** | 373 |
| 分出 10% 给别的养灵者 | 90% | **1.8** | 336（−10%） |
| 对半分 | 50% | 1.0 | 187 |
| 一城 1.2 万人的散修（占 1.2%） | 1.2% | 0.2（钳） | 37 |

**三条硬规则（I6）**：

1. **零和**：`own + Σ granted ≤ 灵脉`。分出去 10%，自己的系数就从 2.0 掉到 1.8——**不是"给别人加 buff"，是"自己变慢"**。
2. **一个生灵只供一个养灵境界**：收到灵量的人练得快，给出的人练得慢，同一年不可重复计算。
3. **只作用于养灵**：锻体 / 炼气 / 修心的任何数值都不吃灵量。

> **为什么用线性而不是 log**：用户要的是"分 10 万 → 剩 90 万"这种**可对账**的减法。log 会把 10% 的损失压成 0.5%，玩家感受不到"分出去"的代价，零和就变成了空话。
>
> **代价**：散修（占比 1.2%）被钳在 0.2，养灵几乎练不动。这是故意的——**养灵必须依附势力**。

## 5. 心性

```text
每年：heart -= 在册 ? 1 : 0.5
      if (heart <= 60) heart -= 0        // 地板，衰减归零
      heart = clamp(heart, 0, 100)
```

- **地板 60，窗口不关**：跌破 90 只影响"心关成功是否给道心"，不影响"能不能再回 90"。
- 回补只走事件：`heart_restore +3~8`、静坐 `+5`（无判定）、了断因果 `+10`。
- **心魔**：`heart < 40` 每年掷一次，存活率 `0.10 × heart / 39`；`heart < 20` 必死。
  - 心魔只对 `body.level ≥ 3 || qi.level >= 2` 的人生效。
  - 存活：`heart = max(10, heart − 5)`，**当前品修为条清零**；死亡：`alive = false`。
  - **注意**：这是心魔的代价，**不属于"突破失败"**，不受 I4 保护。

### 5.1 修心：道心只靠心关

```text
心关成功：道心 += 30 × (心性 / 100)      // 心性 90 → +27，100 → +30
心关失败：+0（不给也不扣）
心性 < 90：成功也不给（只减不增）
门槛：心性 ≥ 90 + 道心达到该品累计值
```

**没有月修为、没有打坐加成、没有功法乘区。** 这是"修心不能靠熬时间"的算术实现：一个资质 100、悟性 100 的人，心性 60，一辈子也涨不了一点道心。

## 6. 气运 `luck`（三个入口，一个都不进乘区）

```text
① 判定修正 = clamp((luck − 50) × 0.001, −0.05, +0.05)     // ±5%，加在 roll 上
② 进位偏置 = 0.5 + (luck − 50) × 0.001                     // 年末修为小数进位概率
③ 事件倾向 = 权重偏移（高气运偏"机缘"，低气运偏"灾祸"）
年度漂移   = sign(50 − luck) × 1                            // 向 50 回归
事件修正   = ±5 ~ ±15
```

- **修为一律保留小数**，年末结算时取整：

```js
const frac = bar - Math.floor(bar);
bar = Math.floor(bar) + (Math.random() < 0.5 + (luck - 50) * 0.001 ? 1 : 0);
```

- **只做加法与时序偏置**，**不进任何乘区**（I5）。`luck` 也不改出生时的偏科系数 `r`。
- **三个入口加起来就是气运的全部**——它不改资质、不改功法、不改灵量。
- **字段名是 `luck`**；`fate` 是命格。

> **为什么连四舍五入都要管**：修为是绝对量、年年累加，小数位年年舍弃就是"慢性扣修为"。让气运决定进位方向，等于让运气好的人每年多捡回零点几个点——一年看不出来，三百年就是几十年。

## 7. 寿元

```js
lifespan = BASE[dao][tier] + rollOnEntry + extraLife

BASE：凡人 72 / 调息 97 / 朝元 120 / 金身 325 / 临虚 1000
      破胎 72（不加）/ 驭凡 165 / 法相 220 / 合一 375 / 化朽 1000
      开视 72（不加）/ 启灵 72（不加）/ 真域 400 / 神游 740 / 浑然 975 / 回春 ∞
      修心 1000 / 1400 / 2000 / 3000

rollOnEntry：进品时掷一次并**存下来**（防读档刷）
extraLife ：延寿丹三档各限一次（+10/+20/+50，累计上限 +80）+ 宝药 + 机缘
品 6      ：**没有任何代价**（r18 确认）。临虚不加不减，化朽/回春同理
```

**叠加，不取 max**：同一份 `extraLife` 加在 400 和 1,000 的底座上都终身有效。旧写法 `max(当前, 下限+rand)` 会把凡人期吃的延寿丹在新境界那天抹掉。

## 8. 结算顺序（每年，角色层）

```js
// 年初（自动，顺序写死）
step1_lifespan(state)      // age+1; age > lifespan → dead
step2_luck(state)          // 向 50 回归 ±1
step3_heart(state)         // 衰减 / 地板
step4_demon(state)         // heart<40 掷；<20 必死
step5_city(state)          // 人口 → 灵脉 → 席位 → 灵量（20 §6）
step6_rollEvents(state)    // 出现概率 → 本年候选 → 主要事件槽（20 §4）

// 月内（玩家驱动，12 个月）—— 见 `20` §6
// 修炼 / 突破 / 求学都是动作，不是步骤

// 年末（自动）
step7_settle(state)        // 错过结算 → 月份清零 → 额度复位 → 跨年推进
```

> **r19 改动**：旧的 `step5_train` / `step6_breakthrough` **已删除**。它们现在是动作，按 `需求/20` §7 的常驻表与 §4 的主要事件驱动；把它们留在年度链里，等于"时间不是货币"（I13）。

**测试要点**：拿一个 `heart = 39` 的存档，跑 step3 前 / step4 前各改一次顺序，结果必须是两个不同的死亡年龄——如果一样，说明顺序没生效。
