## 1. MVC：三层，五个包

整体是 MVC。**数据放数据层，规则放业务层，聚合条件也放数据层**——这一句决定了后面所有模块的边界。

```text
┌─ 表现层 View ────────────────────────────────────────────
│   ui/        面板 · 按钮 · 文案 · 地图 · 日志
│               只读 resolve()，不算公式，不写 state
├─ 业务层 Controller ──────────────────────────────────────
│   engine/    时序：年月初序 · 日历注入 · 池子 · 上桌 · 跨年
│   systems/   一次结算：读 state → 写 state → 产出事件
│   rules/     纯函数公式：月修为 · q · b · 伤害 · 贡献 · 衰减
└─ 数据层 Model ───────────────────────────────────────────
    state/     运行时状态（可序列化、可存档、不含函数）
    data/      静态内容：事件 · 物品 · 身份 · 宏 · 条件组 · 表
```

**依赖只能单向**：View → Controller → Model。反过来就是"公式散在三个地方"，改一处忘两处。

### 1.1 数据层装什么（这是"灵活配置"的全部）

| 数据 | 文件 | 一句话 |
| --- | --- | --- |
| **事件** | `data/events/*.json` | 什么时候、满足什么、选什么、加什么 |
| **常驻动作** | `data/actions.json` | 修炼/坊市/委托/求学/履职 |
| **条件组**（聚合①） | `data/conditions.json` | 把一串 `when` 起个名，事件按名引用 |
| **宏**（聚合②） | `data/macros.json` | 把一串 `do` 起个名（破境、城破、兑换） |
| **模板**（聚合③） | `data/templates.json` | 22 个瓶颈 / 4 座城战共用一份骨架 |
| **日历** | `data/calendar.json` | 战事、主线节点的绝对年份 |
| **物品/身份/天赋/表** | `data/items` `identity` `talents` `tables` | 数值与准入 |
| **上下限** | `data/limits.json` | 每条路径的钳制边界 |

**三层聚合都在数据层**，业务层只提供**算子**（原子效果）和**具名判定器**（连续函数）。所以：

- 改一个门槛 = 改 `conditions.json` 的一行，所有引用它的事件同时变；
- 加一个事件 = 写一行 JSON，引用现成的条件组与宏；
- 加一种全新的效果（"改变天气"）= **唯一要写代码的场景**，在 `ops/` 注册一个算子。

### 1.2 三条铁律

1. **数据层只声明，不计算**：不许出现 `"p": "attr*0.003"`，只能 `{"judge":{"kind":"break","dao":"qi","tier":2}}`。
2. **业务层不认内容**：`rules/` 不认识"洗髓"或"北关"，只认识 `add` / `mod` / `judge`。
3. **表现层不算数**：UI 显示 62 就必须是 `resolve()` 的 62，不许自己加一次洗髓。

## 2. 二十五条不变量（改代码前先对一遍）

| # | 不变量 | 违反会长什么样 |
| - | --- | --- |
| **I1** | 角色属性不进战斗面板；唯一接口是**心性 1:1 → 神志值** | 战力面板出现"资质"，数值膨胀 |
| **I2** | 四条修为条（**内力/法力/灵力/道心**）互不相通，也不跨大境界继承 | 锻体修为能喂养灵 |
| **I3** | 层级只增不减，且**不能跨大境界攒**（Lv1 例外） | 炼气时拿到养灵 Lv3 |
| **I4** | **任何瓶颈失败都不扣修为**；修为条只在本品破境成功时清零（修心为累计制，从不清零） | 失败掉修为，玩家不敢试 |
| **I5** | `luck` 只做**加法与时序偏置**（判定、进位、事件权重），**不进任何境界公式的乘区** | 气运高的人突破率异常 |
| **I6** | **灵量只作用于养灵**的月修为（唯一乘区）；灵量分配是**零和**，分出去就是减法 | 城主锻体也变快；灵量能无限复制 |
| **I7** | 年初判定顺序固定：寿元 → 气运 → 心性 → 心魔 → 城池层 → 掷事件；**修炼/突破/求学不在年度链里**，它们是动作 | 同一年两种结果；时间不再是货币 |
| **I8** | 教育只给**求学动作**（3 月 / +0.03）与**两道门票**（法相 / 养灵 Lv1），不给属性、不给静态概率 | 属性上限被学历顶穿 |
| **I9** | **一年只能发起一次突破**（全局，不分道） | 双修玩家一年连破两道 |
| **I10** | **带动 = 外溢修为 + 拆墙**：只补同品号、只从高阶往低阶、品 1 不带；**不给层级**、不占额度、不做乘法 | 破胎带动了调息，或带动成了"免费跳级" |
| **I11** | 三个子系统（境界 / 法术 / 百艺）**共用一份基数、一份 12 个月**，不许各开一套公式 | 术法白送，境界白练 |
| **I12** | **品 6 无任何代价**（不扣寿元、不清修为、不降层级），瓶颈就是事件条件本身 | 玩家把品 6 当"氪命关" |
| **I13** | **月是唯一时间货币**：一年 12 月，剩余不结转；任何动作必须标价月数 | 出现"免费动作"，时间失去成本 |
| **I14** | **常驻动作不进事件池**：不掷权重、不占优先级槽；主要事件才走"四步入池 + 两步上桌" | 日常动作把瓶颈事件挤掉 |
| **I15** | **强制事件封住常驻**：有未处理的强制事件时，7 个常驻全部不可用 | 玩家用"修炼"把军令拖到明年 |
| **I16** | **出现概率是权重不是概率**：`p = rate / Σrate`；`rate: 10` 只表示"最重"，不表示必出；**要必出用 `forced`** | 把 10 档读成 100%，瓶颈事件反而不上门 |
| **I17** | **主要事件可跨多年，常驻不超过 1 年**（修炼在寿元 ≥ 200 后放宽到 5 年） | 日常动作跨年，月制退化成"一年一决定" |
| **I18** | **配置只声明不计算**：`data/` 里不许出现公式，只能引用已注册的算子与具名判定器 | 事件里写 `"p": "attr*0.003"`，公式散落进 JSON |
| **I19** | **修饰器分永久/临时，永久不进过期队列**；同一路径的结算固定「加→乘→取大→取小→钳」 | 洗髓到期掉了；换配置顺序数值就变 |
| **I20** | **新增内容零代码**：加事件/物品/天赋只改 `data/`；只有新增算子才动代码 | 每加一个事件都要发版 |
| **I21** | **贡献不许换修为、不许换成功率**：`merit` 只能换身份/席位/配额 | 三十年战功直接跳过朝元那道墙 |
| **I22** | **战事由日历驱动**，不进权重池、不看气运；战事期强制事件封住常驻，跨城战/国战不许改 `phase` | 战事变成运气税；国战开着坊市还开着 |
| **I23** | **四道修为各有入口**：`trainMonth(S, dao, months)` 必须指定道，`heart` 传入即报错 | 又退化成"一条梯子" |
| **I24** | **成就线只有一个常量**（`MILESTONE = 4`）：身份、门槛、事件门槛全引用它 | 三处各写一个 4，改一处漏两处 |
| **I25** | **入场券不产生境界**：双四品/太学/师承只写 `cognition.spirit`；`path.spirit.level` 的唯一写入点是 `commit()` | 配置里"毕业即养灵"，一条 mod 跳过大境界 |

## 4. 一条破境的完整数据流

```text
玩家点「冲关」
  → engine.attemptBreakthrough(state, dao, tier)
      ├─ rules.canAttempt(state, dao, tier)     // 一年一次？修为满？层级到？
      ├─ rules.bottleneckOf(dao, tier)          // prob / event_once / event_judge
      ├─ rules.appearRate(state, dao, tier)     // q（**一品只掷一次**，见 11 §4.1）
      ├─ rules.successBase(state, dao, tier)    // b = max(0,属性−40)×0.003
      ├─ rules.breakWall(state, dao, tier)      // 带动②：拆掉低阶同品号的墙
      └─ systems.applyBreakthrough(...)         // 写层级 / 清修为 / 记失败 / 产事件
  → 返回 { ok, why, q, p, roll, cost }
```

**所有随机都发生在 `systems` 层，且必须能被日志复现**（记 `q`、`p`、`roll`），否则玩家投诉时无法举证。

## 5. 状态快照（存什么 / 算什么）

| 存 | 算（读时走链） |
| --- | --- |
| 属性基础值、命格 `fate`、天赋 | 表现值（含所有加成） |
| 修为条当前值、层级、失败累积、尝试次数 | 修炼基数（缓存，三个时机重算） |
| 心性、气运 `luck`、年龄、寿元 | 月修为（基数 × 系数 × 乘区） |
| 学籍、身份、席位、**灵量分配** | 出现率 `q` / 成功基数 `b` |
| 求学加成（按品）、标记 | 战斗面板（除神志值外全部派生） |

**修炼基数可以缓存**，只在**破境 / 换功法 / 属性变化**三个时机重算；`q` 与 `b` 不缓存（`b` 含求学累积与失败累积）。

## 6. 与现有代码的差距（一句话版）

`src/` 6,819 行仍是 r5 之前模型：修为 `PROF_MAX = 100` 百分制、没有 `pathLevel`、`attrCoef = 0.35 + a/65`、心性 3 年 −1 下限 10、气运钳 20–95、事件只有 `kind`（强制闸 16%、门槛闸 45% 硬编码）、**没有月度时间轴**、**没有 `data/` 目录**（事件写在 `src/seed/events.seed.js` 里，是代码）。

**这不是补字段，是五个模块重写**：状态与修饰器（`03`）、配置层（`04`）、事件（`20`）、境界（`11`）、人口（`15`）。顺序见 `91`。
