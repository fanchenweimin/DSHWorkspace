## 1. 从 Godot 借什么

Godot 的组织方式有六个核心概念，我们全部借用，但落到 Web/Node 上：

| Godot 概念 | 含义 | 本项目的对应 |
| --- | --- | --- |
| **Scene（场景）** | 可复用的节点组合，可嵌套 | 一个页面/面板 = 一个 Scene 模块 |
| **Node Tree（节点树）** | 场景实例化成树，父节点管子节点 | DOM 树 + 组件树 |
| **Signal（信号）** | 节点间松耦合通信 | 事件总线（EventBus） |
| **Autoload（单例）** | 全局常驻服务 | 全局 store / service |
| **Resource（.tres）** | 数据与配置资产，可被编辑器改 | SQLite 表 + JSON 资产 |
| **Group / Export** | 分组查询、字段暴露 | 标签查询、ViewModel 字段白名单 |

### 1.1 为什么值得这么组织

现在的问题：

- `engine.js` 3000 行，状态机、规则、序列化、权限裁剪全在一起。
- `game.js` 1000 行，渲染、请求、事件绑定揉在一起。
- 加一个新事件类型要改五个地方，加一个字段要改三个地方。

Godot 的答案：**场景只做自己那点事，通信靠信号，数据靠资源**。这套搬到 Web 上同样成立。

## 2. 全局分层（MVC）

```text
┌──────────────────────── 浏览器（View + 轻 Controller）────────────────────────┐
│                                                                              │
│   Scene/Game  ──signal──►  EventBus  ──►  Controller                          │
│        ▲                                     │                               │
│        │                                     │ HTTP (command)                │
│        └──────── ViewModel(state) ◄──────────┘                               │
│                                                                              │
└──────────────────────────────────┬───────────────────────────────────────────┘
                                   │
┌──────────────────────────────────▼───────────────────────────────────────────┐
│                          服务端（权威 Model）                                  │
│                                                                              │
│  Router ──► Controller ──► Service/UseCase ──► Model(Domain)                  │
│                │                                    │                         │
│                │                                    ├─ Rules（纯函数）         │
│                └──► Serializer（按 viewer 裁剪）◄───┤  State（可变状态）       │
│                                                     └─ Repository（SQLite）    │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 2.0 命名对照：本文的 MVC 与 `设计/00` 的 MVC

两处都叫 MVC，切法不同，**边界是同一套**，别按名字对：

| `设计/00`（概念层） | 本文（落地层） | 说明 |
| --- | --- | --- |
| 数据层（`state/`） | `model/state` | 单局状态 |
| 数据层（`data/`） | `seed/` + `data/`（JSON） | 内容资产：事件、条件组、宏、模板、日历 |
| 业务层（`rules/`） | `model/rules` | **纯函数，无副作用** |
| 业务层（`systems/`、`engine/`） | `model/systems` + `service/` | 一次结算 / 一次用例 |
| 表现层（`ui/`） | `view/*` + `controller/serializer` | 只画、只裁剪 |

**一句话**：本文的 Model 是"服务端权威模型"，它同时装着 `设计/00` 说的数据层与业务层；**Controller 是命令层（一次玩家动作）**，不是 `设计/00` 里的"业务层"。读哪份文档，就用哪份的名字。

### 2.1 Model（模型）＝ 真理所在

**服务端唯一权威**。客户端不持有任何可写模型。

| 子层 | 职责 | 例子 |
| --- | --- | --- |
| `model/state` | 定义单局状态结构、默认值、字段约束 | `createState()`、字段表 |
| `model/rules` | **纯函数**，输入 state + 参数，输出结果或新 state | `suppress()`、`realmAttribute()`、`breakthroughChance()` |
| `model/systems` | 有副作用的领域系统（会改 state） | `training`、`breakthrough`、`combat`、`economy` |
| `model/repository` | 持久化边界 | `runRepo`、`configRepo`、`eventRepo` |

**硬规则**：`rules` 里不许出现 `Math.random()` 之外的 IO，不许碰 DOM、不许碰 SQLite。随机源统一从 `Rng` 注入，便于测试。

### 2.2 Controller（控制器）＝ 一次动作

**用例粒度**，一个函数处理一个玩家动作（command）：

```js
// controller/commands/choose.js
async function choose({ runId, choiceId, rev, viewer }) {
  const state = await runRepo.load(runId);
  assertRev(state, rev);
  const result = engine.choose(state, choiceId);   // 调 model
  await runRepo.save(state);
  return serializeState(state, viewer);            // 调 serializer
}
```

| 子层 | 职责 |
| --- | --- |
| `controller/http` | 路由、参数解析、鉴权、错误映射 |
| `controller/commands` | 一个玩家动作一个文件 |
| `controller/serializer` | **按 viewer 裁剪**（见 §7） |

### 2.3 View（视图）＝ 只画，不算

| 子层 | 职责 |
| --- | --- |
| `view/scenes` | 页面级或面板级模块，有 `mount/unmount/update` |
| `view/components` | 可复用小组件（选项按钮、属性条、时间流） |
| `view/bindings` | 把 ViewModel 映射成 DOM，不包含业务判断 |
| `view/styles` | CSS，按 scene 分文件 |

**硬规则**：View 里**不许出现规则计算**。看到 `if (realm.stageIndex >= 4)` 这种就说明该下沉到 Model。

### 4.2 Scene 契约

每个 Scene / Panel 都是同一个形状，便于替换：

```js
export function createEventPanel() {
  let root = null;
  return {
    mount(host, props) { /* 建 DOM，一次性 */ },
    update(vm) { /* 增量更新 */ },
    unmount() { /* 解绑、清空 */ },
    onSignal(name, handler) { /* 可选 */ }
  };
}
```

**只允许 `update(vm)` 重绘，不允许 scene 自己发请求**。请求一律走 Controller。

## 5. 信号总线（Bus）

Godot 的 signal 搬到浏览器，就是一个极简 EventEmitter。

### 5.1 信号清单

| 信号 | 发出者 | 载荷 | 接收者 |
| --- | --- | --- | --- |
| `state:changed` | Store | 新 state | 所有 Panel |
| `choice:pick` | EventPanel | `choiceId` | GameController |
| `choice:blocked` | EventPanel | `{reason}` | Toast |
| `ambient:advance` | AmbientPanel | `index` | TimelineNode |
| `ambient:finish` | AmbientPanel | — | GameController |
| `drawer:open` | 任意 | `kind` | DrawerRoot |
| `drawer:close` | DrawerRoot | — | — |
| `combat:action` | CombatPanel | `actionId` | GameController |
| `breakthrough:pick` | BreakthroughPanel | `methodId` | GameController |
| `realm:focus` | RealmRailNode | `realmKey` | GameController |
| `training:start` | TrainDrawer | `{kind, skill, years}` | GameController |
| `task:accept` | TaskDrawer | `taskId` | GameController |
| `market:buy` | MarketDrawer | `itemId` | GameController |
| `error` | Api | `{code, message}` | Toast |
| `session:changed` | Session | `user` | HeaderNode |

### 5.2 为什么用总线而不是层层回调

- 现状：`game.js` 里 `addEventListener` 绑了十几个 `data-*`，闭包互相引用。
- 总线之后：Panel 只管发信号，Controller 只管收信号，互不知道对方存在。
- 加一个抽屉不用改 GameScene。

## 6. Autoload（单例）职责

| 单例 | 职责 | 不做什么 |
| --- | --- | --- |
| `Session` | 当前用户、角色判定 | 不碰游戏数据 |
| `Store` | 持有 `state`，计算 `ViewModel` | 不直接发请求 |
| `Api` | fetch 封装、错误归一 | 不含业务规则 |
| `Bus` | 信号收发 | 不含逻辑 |
| `Toast` | 提示 | — |

### 6.1 Store 与 ViewModel

```js
// autoload/store.js
let state = null;

export const Store = {
  setState(next) {
    state = next;
    Bus.emit('state:changed', next);
  },
  getState: () => state,

  // ViewModel：给 View 用的、已经算好的展示字段
  viewModel() {
    const s = state;
    if (!s) return null;
    return {
      age: s.age,
      calendar: s.calendar.label,
      identity: s.identity,
      education: s.education,
      realms: s.realms,          // 已经是展示结构
      phase: s.phase,
      event: s.event,
      ambient: s.ambient,
      result: s.result,
      bottleneck: s.bottleneck,
      battle: s.battle,
      ending: s.ending,
      mandatory: s.mandatory,
      actions: s.actions           // 常驻行动（修炼/委托/破境）
    };
  }
};
```

**ViewModel 是 View 的唯一输入**。View 不再自己 `state.realms.find(...)`。

## 7. 序列化与权限（Serializer）

这是 MVC 里最容易被做错的一层，所以单列。

### 7.1 三层输出

```text
model.state （完整，含隐藏）
    │
    ├─ serializeState(state, 'sysadmin')  → 完整（含 tags/changes/warning）
    ├─ serializeState(state, 'user')      → 玩家视图（无 tags/changes）
    └─ serializeState(state, 'guest')     → 与 user 相同
```

### 7.2 白名单而非黑名单

```js
// controller/serializer/state.view.js
const PLAYER_FIELDS = ['id','age','calendar','identity','education','realms',
  'phase','event','ambient','result','bottleneck','battle','ending',
  'mandatory','actions','journal'];

function serializeState(state, viewer) {
  const vm = buildViewModel(state);          // model → 展示结构
  if (viewer === 'sysadmin') return vm;
  return pick(vm, PLAYER_FIELDS);            // 白名单裁剪
}
```

**永远不要在 View 里判断角色**。角色只在序列化时用一次。

## 8. 数据流：一次点击的完整链路

以「玩家点了一个选项」为例：

```text
1. choice.node.js  点击
       ↓ Bus.emit('choice:pick', choiceId)

2. game.controller.js  收到信号
       ↓ Api.post('/api/runs/:id/choose', { rev, choiceId })

3. src/router   路由到 run.controller
       ↓

4. run.controller  鉴权、读 body、assertRev
       ↓

5. RunRepo.load(runId)  → state

6. model/systems/event.system.choose(state, choiceId)
       ├─ rules/ 判成功率（纯函数）
       ├─ systems/ 应用效果
       └─ 返回 { state, result }

7. RunRepo.save(state)

8. serializer/state.view.js  按 viewer 裁剪
       ↓ JSON

9. client: Api 收到
       ↓ Store.setState(json.state)

10. Bus.emit('state:changed')
       ↓

11. GameScene → 选一个 Panel → panel.update(vm)
```

**每一层只做一件事**，而且断点可以精确插在任意一层。

## 9. 八类事件在架构里的落点

| # | 类 | Slot | 抽取器 | Panel | 说明 |
| --- | --- | --- | --- | --- | --- |
| ① | `ambient` | 槽位（低） | `event.system.drawAmbient()` | `AmbientPanel`（时间流） | 无选项，逐年展示 |
| ② | `normal` | 槽位（低） | `drawNormal()` | `EventPanel` | 主剧情 |
| ③ | `encounter` | 槽位（低） | `drawEncounter()` | `EventPanel` | 同上，样式可区分 |
| ④ | `cultivate` | 常驻 | — | `TrainDrawer` | 永远可选 |
| ⑤ | `forced` | 槽位（最高） | `drawForced()` | `EventPanel`（强制标记） | 压制一切 |
| ⑥ | `commission` | 常驻 | `refreshCommissions()` | `TaskDrawer` | 按年刷新 |
| ⑦ | `threshold` | 槽位（中） | `drawThreshold()` | `EventPanel`（门槛标记） | **门槛事件链**，正常概率 |
| ⑧ | `breakthrough` | 槽位（条件必出） | `drawBreakthrough()` | `BreakthroughPanel` | 修为满时必出 |

### 9.1 抽取器是独立模块

```js
// model/systems/event.system.js
export function drawNext(state, rng) {
  const forced = drawForced(state);              // ⑤ 最高
  if (forced) return forced;

  const bt = drawBreakthrough(state);            // ⑧ 条件必出
  if (bt) return bt;

  const ratio = pickRatio(state);                // 按状态取区间
  const r = rng.next();
  if (r < ratio.ambient) return drawAmbient(state, rng);
  if (r < ratio.ambient + ratio.encounter) return drawEncounter(state, rng);
  return drawWeightedNormalOrThreshold(state, rng);  // ② 与 ⑦ 同池按权重
}
```

每个 `drawXxx` 都是纯函数（除 rng），可单测。

### 9.2 门槛事件链的数据结构

```js
// seed/events.seed.js 里的链定义
{
  id: 'chain_heart',
  kind: 'threshold',
  steps: [
    { event: 'life_chain',          requires: { flags: { near_death: true } } },
    { event: 'great_awakening',     requires: { flags: { life_and_death: true } } },
    { event: 'awakening_complete',  requires: { flags: { awakening_seed: true } } }
  ],
  grant: 'heart_open',              // 走完后授予的资格
  blockedBy: { heart: { min: 90 } } // 心性不到 90，链停在原地
}
```

抽取器按 `steps` 顺序检查，第一个满足 `requires` 且未完成的就是「下一步」。

## 11. 前端 Scene 的渲染约定

### 11.1 Panel 选择

`GameScene.update(vm)` 只做一件事：根据 `vm.phase` 选 Panel。

```js
switch (vm.phase) {
  case 'event':
    active = {
      ambient:      ambientPanel,
      threshold:    thresholdPanel,
      breakthrough: breakthroughPanel,
      forced:       eventPanel,
      normal:       eventPanel,
      encounter:    eventPanel
    }[vm.event.kind] || eventPanel;
    break;
  case 'result':      active = resultPanel; break;
  case 'battle':      active = combatPanel; break;
  case 'ended':       active = endingPanel; break;
}
```

### 11.2 不换行布局

选项节点固定三行结构：

```text
[字母] 标题 ......................... 约 N 年
       提示 · 标签（sysadmin 才有）       
```

CSS 用 `grid-template-columns: 34px minmax(0,1fr) auto`，第二行 `flex-wrap: nowrap` + `overflow-x:auto`。
**永远不折行**，超宽横向滚动。

### 11.3 ambient 时间流

`AmbientPanel` 挂载 `TimelineNode`：

```text
逐年条目 → 淡入 → 停留 2–3 秒 → 下一条
右上角：加速 ×1 ×2 ×4 ×8
全部播完 → 发 'ambient:finish' → Controller 请求 continue
```

不提供「跳过」，只能加速。

## 14. 已确认的设计决定

| # | 决定 | 结论 |
| --- | --- | --- |
| 1 | 目录结构 | **`src/` + `public/`**（Node 项目常规，见 §3） |

### 14.1 Scene 契约（可扩展）

```js
export function createXxxScene() {
  return {
    // 必需
    mount(host, props),      // 建 DOM
    update(vm),              // 增量更新
    unmount(),               // 清理

    // 可选（需要时再实现）
    onEnter(), onExit(),
    onResize(),
    handleSignal(name, payload)
  };
}
```

只有 `mount/update/unmount` 是强制的，其余按 Scene 需要自行添加，不做统一约束。
