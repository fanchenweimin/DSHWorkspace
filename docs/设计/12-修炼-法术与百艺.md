## 1. 术法：数据与公式

```js
const ARTS = {
  grade: 'huang_zhong',      // huang_xia | huang_zhong | huang_shang | xuan | di | tian
  kind: 'mana',              // physical | mana | spirit | dao
  unlock: { min: 1, best: 2, max: 2 },   // 品（由阶位梯子写死，不可自由填）
  power: { base: 30, scale: 1.0 },       // 基础威力 + 属性系数
  passive: [{ stat: 'attack', value: 0.08 }],  // 学成即生效，随熟练缩放
  affinity: 'neutral',       // neutral | good | evil（与本性比对）
  sideEffect: null           // 见 §1.3
};
```

### 1.1 阶位系数与品级梯子

| 阶位 | 对应品 | 入门 min | 最适 best | 最高 max | 阶位系数 |
| --- | --- | --- | --- | --- | --- |
| 天 | 品 6 | 5 | 6 | 6 | **8** |
| 地 | 品 5 | 4 | 5 | 5 | **5** |
| 玄 | 品 4 | 1–3 | 4 | 4 | **3** |
| 黄上 | 品 3 | 1 | 3 | 3 | **2** |
| 黄中 | 品 2 | 1 | 2 | 2 | **1.5** |
| 黄下 | 品 1 | 1 | 1 | 1 | **1** |

**由上往下兼容**：`min(天) = best(地)`，`min(地) = best(玄)`。写成代码就是查常量表，不要用相对公式推——相对公式会在"玄阶 min=1"这条上崩掉（玄阶是唯一 min 与上一档 best 不相邻的阶位）。

**效果曲线**（沿用物品三重境界）：
```text
品 < min          → 不能修
min ≤ 品 < best   → 威力 40% → 100% 线性
best ≤ 品 ≤ max   → 100%
品 > max          → 50%（换代需求）
```

### 1.2 熟练度

```text
月熟练 = 修炼基数 × 0.20 ÷ 阶位系数 × 相性系数
熟练度 0–100（每本独立），档位：入门 0–39 / 大成 40–79 / 圆满 80–100
威力倍率：×1.0 / ×1.4 / ×1.8
被动加成 = passive.value × (0.5 / 1.0 / 1.5)      // 入门/大成/圆满
同类被动相加，封顶 +50%
```

**时间账（修炼基数 57.2 = 锻体、资质 60、黄上功法 46、品 3）**：

| 阶位 | 月熟练 | 入门（40） | 圆满（100） |
| --- | --- | --- | --- |
| 黄下 | 11.4 | 3.5 月 | 8.8 月 |
| 黄中 | 7.6 | 5.3 月 | 13.2 月 |
| 黄上 | 5.7 | 7.0 月 | 17.5 月 |
| 玄 | 3.8 | 10.5 月 | 26.3 月 |
| 地 | 2.3 | 17.4 月 | 43.5 月 |
| 天 | 1.4 | 28.0 月 | **70 月（5.8 年）** |

> 基数 57.2 的来历：`0.70 × 60 + 0.20 × 46 + 0.10 × 60 = 42 + 9.2 + 6 = 57.2`。
> 旧文那张表用的是 75（旧式子 `主属性 ×(0.7+0.15×品阶) + 品×2`），**新口径整体慢 30%**——结论方向不变：天阶术法要将近六年，等于把境界往后推六年。

### 1.3 相性与副作用

```js
function affinityFactor(state, art) {
  if (art.affinity === 'neutral') return { rate: 1.0, power: 1.0, heart: 0 };
  const aligned = (art.affinity === 'evil') === (state.nature <= 40);
  return aligned
    ? { rate: 1.0, power: 1.0, heart: 0 }
    : { rate: 0.5, power: 0.8, heart: [3, 10, 20] };   // 入门/大成/圆满各扣一次
}
```

**里程碑扣心性只在跨档时结算一次**，不是每次加点都扣。写 `art.heartPaid = {ruMen:true, daCheng:false, yuanMan:false}` 三个布尔，避免重入。

副作用写成数据，不写成代码分支：

```js
sideEffect: { type: 'drift_nature', target: 40, amount: 1, period: 'year', stopAt: 40 }
sideEffect: { type: 'shrink_stat',  stat: 'spiritMax', ratio: 0.30, limitUses: 4 }  // 第4次死
```

### 1.4 获取渠道（六档，写死在配置里）

| 阶位 | 渠道 | 触发 | 备注 |
| --- | --- | --- | --- |
| 黄下 | 蒙学 / 坊市白送 | 无 | `price = 0` |
| 黄中 / 黄上 | 坊市 | 进店 | 货架上限就是黄上 |
| 玄 | 城主府 / 宗门 / 家族 | **身份事件，forced** | `price = 0`，付的是功劳 |
| 地 / 天 | 机缘事件 | 概率 | `purchaseable: false` |

**校验点**：坊市货架 `shelfMax = 'huang_shang'`。任何把玄阶塞进货架的配置都是 bug。

## 2. 百艺

### 2.1 基数与积累

```text
百艺基数 = 资质 × w资 + 悟性 × w悟           (w资 + w悟 = 1)
月积累   = 百艺基数 × 0.20

升阶阈值：1 → 2 累计 600；2 → 3 累计 1,800
```

**百艺不加工法值、不加境界值**——它不是"又一条修炼条"，是"吃饭的手艺"。用户口径：「百艺品阶与修炼差不多，其受到资质与悟性两项属性影响，是一个加权和」（`需求/13` §11.0 为准）。

| 场景 | 基数 | 月积累 | 到 600 | 到 1,800 |
| --- | --- | --- | --- | --- |
| 资 60 / 悟 60（各 0.5） | 60 | 12.0 | 50 月（4.2 年） | 再 100 月（共 12.5 年） |
| 资 50 / 悟 55 | 52.5 | 10.5 | 57 月（4.8 年） | 再 114 月（共 14.3 年） |
| 资 75 / 悟 80 | 77.5 | 15.5 | 39 月（3.2 年） | 再 77 月（共 9.7 年） |

**w资 / w悟 按门类分**：丹道偏悟（0.3/0.7）、炼器偏资（0.7/0.3）、符箓各半（0.5/0.5）。权重和恒为 1。

### 2.2 天赋

| 天赋 | 效果 | 能否后天获得 |
| --- | --- | --- |
| 无 | 上限 2 阶（匠） | — |
| 有 | 上限 3 阶（师） | 否 |
| 卓绝 | 上限 4 阶（宗师），且月积累 ×1.5 | 否 |

**天赋不通过修炼获得**（转世也不保留）。这是"百艺是投胎的彩票"的机制实现。

### 2.3 三个产出接口

| 产出 | 实现 |
| --- | --- |
| 钱 | 做工月 → `income = 品阶系数 × 月数 × 天赋系数` |
| 辅助修炼 | 产出丹药/符箓/阵盘，直接进 `inventory`，与坊市同价折算 |
| 战斗手段 | 器物四档（粗制/精制/法器/灵器），战斗读 `equipment` |

## 3. 时间预算（三子系统共用的调度）

```js
// 年度行动：玩家分配 12 个月
const months = { realm: 8, art: 3, craft: 1 };

// 境界
path.bar += base * 0.20 * months.realm;
// 术法
art.prof += base * 0.20 / gradeCoef * affinity * months.art;
// 百艺
craft.acc += craftBase * 0.20 * months.craft;
```

**三条断言**：

1. `realm + art + craft ≤ 12`，超出直接拒绝（不是静默截断）。
2. **长跨度行动（闭关/游历）不可拆月**：一次闭关 3 年就锁定 36 个月的分配比例，中途不能改。
3. **修心不走 `months.realm`**：修心没有月修为，它的进度由心关事件推进（`11` §5.1）。修心者把月份全投给术法与百艺是合法的。

## 4. 边界与断言

| 场景 | 期望 |
| --- | --- |
| 熟练度 > 100 | 钳 100，不溢出 |
| 被动加成合计 > 0.5 | 钳 +50% |
| 阶位 `min` 不满足 | 不能修，`require` 为假，不入池 |
| 品 > `max` | 威力 ×0.5，不禁止使用 |
| 相性错配 | 进度 ×0.5，威力 ×0.8，跨档扣心性一次 |
| 同一里程碑重复进入 | `heartPaid` 布尔挡住，不重复扣 |
| 玄阶出现在坊市 | 配置校验直接报错 |
| 月数合计 > 12 | 拒绝本次分配 |

## 5. 与旧文档的差异

| 旧 | 新 |
| --- | --- |
| `月熟练 = 2 + 悟性 × 0.06` | `基数 × 0.2 ÷ 阶位系数 × 相性` |
| 术法不吃修炼基数 | 吃**同一份**基数 |
| 百艺基数 `资质×w资 + 悟性×w悟`（和 = 1） | **不变**（百艺不加工法、不加境界值） |
| 术法、百艺与境界互不影响 | **三者抢同一份 12 个月**，写进 `months` |
| 恶术有硬资格门槛 | 无门槛，代价即门槛 |
