# 文档索引（第 35 版 · 2026-11-08 整理）

`docs/` 只放两个目录：

- **`需求/`**——"要什么"。你的口径、规则、边界，中文写，不写代码。
- **`设计/`**——"怎么做"。公式、表、伪代码、校准、实施顺序。

**无效文档全部在 `归档/`（工作区根目录，不在 docs 里）**，只作史料，**一律不作准**。

### 文档优先级

1. **`docs/需求/` + `docs/设计/`** —— 第一权威。冲突时以这里为准。
2. **`归档/*.md`** —— `docs/` 里找不到、或不知道怎么改时，回这里翻。
   迁移时确实丢过东西（例：「修为总量」的定义只在 `归档/境界系统总纲.md` §188，
   正是 r28 修 `barMax` 的依据）。**归档不作准，但它是"被删掉的原文"的仓库。**
3. ~~`.tmp/*.md.bak2`~~ —— **本版已清理**。`.tmp` 里只剩一个 `cdp.js`
   （无头 Chrome 验证脚本，三份根文档都引用它）。原有草稿里**还有效的冲突项**
   已收进 `需求/99-待裁决-历史定稿冲突.md`。

> 代码改动后**必须同步 docs**（需求 → 设计 → 代码 → 本文件/PROGRESS）。三处不一致视同 bug。
> **代码与文档到底差在哪，看 `设计/92-实现差异台账.md`**（2026-11-08 全量核对，逐条带文件:行）。

两份目录**同名同号**，`需求/11` 对应 `设计/11`，改一边必须改另一边。

**实现代码在 `src/` 与 `public/`（工作区根目录）**，不在 `docs/` 里。它是「需求 → 设计 → 实现」的第三个落点：

- `src/seed/*.json` 是**数据层**的实物（**17 份**），字段名与 `设计/01`、`设计/04` 逐字对齐；`schema.json` 是**配置字典**（字段中文名 / 列宽 / 哪些路径只读），配置页只读它；
- `src/model/rules/` 是**公式层**：`dsl.js` 条件求值、`mods.js` 修饰器管线、`realm.js` 月修为 / 出墙率 / 破境判定、`grade.js` 阶+品、`time.js` 耗时、`spells.js` 术法、`arts.js` 百艺、`battle.js` 战斗；
- `src/model/systems/` 是**业务层**：`hand.js` 算六块手牌 + 坊市货架、`draw.js` 抽事件、`effects.js` 执行 `do`、`turn.js` 结算时间与顺序、`calendar.js` 战事日历、`opening.js` 开局入品；
- `src/controller/serialize.js` 是**裁剪层**：唯一允许决定"玩家能看到什么"的地方；
- `public/` 是**表现层**（地图 / 游戏 / 配置 / 登录），原生 ES，不打包。
- 跑法：`node start.js` → `http://127.0.0.1:8787`；断言：`node test/smoke.js`（73 项）。
  **哪些实现了、哪些没实现，先看 `设计/92`（差异台账），再看 `PROGRESS.md`（进度）。**
